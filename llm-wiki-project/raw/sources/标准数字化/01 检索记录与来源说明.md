## 一、这次要采集什么

用户给定的入口是全国标准信息公共服务平台（std.samr.gov.cn）的**标准检索页**，查询词为
“标准数字化”。目标是把该检索能命中的标准资料，落到
`llm-wiki-project/raw/sources/标准数字化/`，再交给 LLM Wiki 摄入。

## 二、检索入口的实际行为

`https://std.samr.gov.cn/search/std?q=标准数字化` 本身**不渲染结果**：
它是一个检索外壳页，结果放在页面内嵌的 iframe 里。把它拆开看是这样：

```html
<iframe src="https://std.samr.gov.cn/search/stdPage?q=标准数字化&tid=" id="myiframe" ...>
```

所以**真正的结果页**是 `https://std.samr.gov.cn/search/stdPage?q=标准数字化&tid=`。
本次采集先按各标准库自己的查询接口逐库核对，再回到这个统一结果页做总账核对，两条路得到的结果一致。

各库接口与实际命中：

| 标准库 | 接口 | 命中 |
| --- | --- | --- |
| 国家标准 | `POST https://std.samr.gov.cn/gb/search/gbQueryPage`，表单字段 `searchText` | 5 |
| 行业标准 | `POST https://hbba.sacinfo.org.cn/stdQueryList`，表单字段 `key` | 1 |
| 地方标准 | `POST https://dbba.sacinfo.org.cn/stdQueryList`，表单字段 `key` | 0（精确词未命中） |
| 团体标准 | `https://www.ttbz.org.cn/` | **未取到**，站点返回 Web 应用防火墙的人机识别页 |
| 企业标准 | `https://www.qybz.org.cn/` | **未检索**（独立账号体系，不在本次范围） |

国家标准库的查询命令（可复现）：

```bash
curl -s -X POST "https://std.samr.gov.cn/gb/search/gbQueryPage" \
  -H "Content-Type: application/x-www-form-urlencoded; charset=UTF-8" \
  --data-urlencode "searchText=标准数字化" \
  --data "sortOrder=asc&pageNumber=1&pageSize=50"
```

统一结果页给出的是**模糊关键词命中**，共 **17 条**（抓取日期 2026-10-12）：

```bash
curl -s "https://std.samr.gov.cn/search/stdPage?q=标准数字化&tid="
```

## 五、正文从哪里来

标准元数据来自 std.samr.gov.cn 与各库详情页，**已逐字抓取**。

标准正文的获取情况分三种：

1. **公开征求意见稿（已获取，6 份）**——中国标准化研究院于 2025-04-30
   发布《关于对〈标准数字化 第2部分：参考架构模型〉等6项推荐性国家标准征求意见的函》，
   附件包含 6 项标准的征求意见稿与编制说明，可公开下载：
   <https://www.cnis.ac.cn/wap/dh/bydt/bzyjzq/gbzqyj/202504/t20250430_59942.html>
   （抓取日期 2026-10-12）。这些是**发布前的草案**，不等于正式发布版本。
2. **出版方摘录的“范围”条款（已获取）**——中国标准在线服务网
   （`https://www.spc.org.cn/online/<hcno>.html`）为每份标准提供简介与适用范围摘录。
   这是出版方的转录，作为二手来源保留。
3. **正式发布版全文（未获取）**——国家标准全文公开系统
   （`https://openstd.samr.gov.cn/bzgk/std/newGbInfo?hcno=<hcno>`）提供在线阅读，
   阅读页对页面图像做了防批量下载处理。本次**没有绕过该处理**，
   因此只登记入口 URL，不保存正文。需要条款级引用时，应在该系统在线阅读或购买正式出版物。

+ 第 5 份正文多切出的 1 份），PDF 7 份。

没有文字层，只能作为留档，无法被文本检索。

**为什么草案只有 6 份、档案却有 9 份**：公开征求意见时只挂了 6 项标准。
GB/T 48000.1-2025、GB/T 46917.3-2026、YC/Z 650-2026 这 3 项没有公开草案，
所以只有档案、没有正文。

**为什么正文和编制说明要拆开**：它们本来就是两份不同的文件。拆开后单份体积更小，
GB/T 46917.1 的正文因此不再超出 LLM 的处理上限（该份另按章切成上、下两个文件）。

**文本版是怎么来的**：按 PDF 的字体、字号、缩进与表格区域重建结构——
表格还原为 Markdown 表格，标题层级与条编号按原文档还原，
页眉页码已剔除，跨页段落已接回。二级条编号（如 6.1、6.2）在部分 PDF 的文本层中缺失，
按出现顺序重建，并用其下的三级条编号交叉核对过。**未做人工校对**，引用条款请回到 PDF 核对。
