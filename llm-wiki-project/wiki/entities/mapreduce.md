# MapReduce

MapReduce 是一种分布式批处理计算框架，用 Map 与 Reduce 两个函数描述分片计算与结果汇总。视频作者在《第 3 集｜一口气讲透大数据、数据库、数据仓库、数据湖、数据中台的底层原理》中称其为大数据分布式计算的鼻祖。

## 定义

视频作者在该段口播中给出的机制：

- 思路与分布式存储一样——切分：把全量数据拆成一个个小分片，分给多台服务器并行计算，最后再把结果聚合起来。
- **Map 函数**告诉每台机器，本地分片里的每行数据怎么处理，比如算销售额就提取每笔订单的金额、算出本地分片的总金额。
- **Reduce 函数**告诉系统，所有机器的局部结果怎么汇总，对销售额就是把上千台机器的本地总额全部加起来，得到总销售额。
- 这套"数据分片 → Map 本地计算 → Reduce 汇总结果"的通用计算框架就是 MapReduce。

## 来源观点

作者认为，靠多机并行处理，原本需要几天的统计任务几分钟就能跑完。但它有个硬伤：计算过程中的所有中间结果都会写入磁盘，频繁的磁盘 I/O 拖慢了速度，只适合对时效性要求不高的离线任务。

## 已核验事实

无。MapReduce 作为 Apache Hadoop 项目的计算模型属于公开技术事实（可独立核验的背景知识），但本集给出的性能量级（几天 → 几分钟）为作者口播估计，`unknown / 待外部核验`。

## 项目分析

MapReduce 在本集叙事中承担"算"这一环节的起点，与 [[entities/spark]]、[[entities/flink]] 构成一条演进线：磁盘 I/O → 内存化 → 流式。作者用"中间结果落在磁盘还是内存"解释性能差异，这一解释属于 [[concepts/数据移动成本视角]]。

## 反例或边界

- 作者未讨论 MapReduce 在迭代计算、交互式查询场景下的局限。
- 作者未讨论磁盘 I/O 之外的其他性能因素。
