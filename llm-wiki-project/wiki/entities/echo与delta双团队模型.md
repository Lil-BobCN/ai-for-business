# Echo 与 Delta 双团队模型

Echo 与 Delta 双团队模型是视频作者在《AI+企业》第 3 集中描述的一种组织设计，据称由 Palantir 在初期招聘与项目扩展中发展出来：Echo 是嵌入分析师侧，Delta 是部署工程师侧，两者相加构成一个完整的创业团队。团队名称来自 ASR，`Echo` 在转写中曾作 `Aco`，名称待确认。

## 来源观点

视频作者在该段口播中提出：

- **Echo 团队**是嵌入分析师，负责理解客户需求、管理客户关系，带有一定的 sales 属性，去定义方案。这类人才来源更多是行业专家，需要具备技术容纳度与技术理解力，是行业领域专家与技术理解力的复合人才。
- **Delta 团队**更偏工程，是部署工程师，负责快速写代码、做原型，接近于创业公司联合创始人这种气质和风格。
- 两个角色加在一起就是一个完整的创业团队。作者据此解释为什么 Palantir 出来的人有很多都去创业了：他们接触了客户的很多需求，搭配在一起就可以打造一个初创团队，因为这就是创始人需要的全套技能。
- 作者引 `Bob MacGuru`〔人名待确认〕反复强调的一点：Delta 团队的工程师不是那种追求抽象、完美代码、能维护十年十二年的工匠型工程师，FDE 需要的是能够快速交付、不怕第一版代码要扔掉的人。

## 已核验事实

本页所依据的视频存在与结构已核验；团队名称、职责划分与人才来源均属视频作者主张，未经独立核验。

## 项目分析

该模型解释了 FDE 组织为什么需要两类不同气质的人，也解释了 Palantir 人才外溢到创业生态的现象。它与 [[土路与柏油高速路]] 机制配套：Echo 负责识别需求与关系，Delta 负责快速修土路，总部产品团队负责把土路抽象成高速路。与 [[fde交付方法]] 中的三阶段流程（Audit/评估/Deployment）可交叉引用。

## 反例与边界

- 团队名称来自 ASR，`Echo` 曾作 `Aco`，需以视频原片复核。
- 作者未给出该模型的实际规模、汇报关系或与产品团队的接口细节。
- 该模型是否适用于 Palantir 之外的组织，作者未讨论。
