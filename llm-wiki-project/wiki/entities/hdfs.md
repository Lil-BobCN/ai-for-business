# HDFS

HDFS（Hadoop Distributed File System）是 Hadoop 生态中的分布式文件系统，用于在大量普通服务器上存储超大文件。视频作者在《第 3 集｜一口气讲透大数据、数据库、数据仓库、数据湖、数据中台的底层原理》中把它描述为数据湖早期经典的底层存储介质。

## 定义

视频作者在该段口播中给出的设计思路：

- 单台服务器硬盘装不下 PB 级大文件，就把文件切成默认 128 兆的小数据块，分散存到上千台普通服务器上。
- 每个数据块存三个副本、放到不同机器，就算某台服务器磁盘坏了，也能从其他副本恢复。
- 整个集群分为两个核心角色：**NameNode** 当总管，专门记录哪个文件的哪个块存在哪台服务器的所有信息，相当于图书馆的目录；**DataNode** 当工人，实际存储数据块，相当于书架。
- 读写文件时先问 NameNode 找位置，再直接去对应 DataNode 操作。

## 来源观点

作者认为，HDFS 本质也只是一块超级裸硬盘，只管存文件，没有分类标签和权限管理。因此数据湖在 HDFS 之上补充了一整套管理能力：数据接入工具负责把数据拉入湖里；元数据管理负责记录数据湖里有什么数据、存在哪；数据目录负责给数据分类打标签；还有细粒度的权限控制。作者补充，目前行业主流已从自建 HDFS 转向云对象存储：它不用运维、弹性扩容，1 TB 存储成本仅几十元，性价比更高。

## 已核验事实

无。HDFS 作为 Apache Hadoop 项目的分布式文件系统属于公开技术事实（可独立核验的背景知识），但本集给出的具体参数（默认 128 兆块、三个副本）与云对象存储价格（1 TB 几十元）为作者口播主张，`unknown / 待外部核验`，且价格会随厂商与时间变化。

## 项目分析

HDFS 在本集叙事中承担"存"这一环节的早期代表，与 [[concepts/数据湖与数据沼泽]] 的治理缺口直接相关：作者用"超级裸硬盘"这一比喻说明存储介质本身不提供治理能力，治理必须由上层组件补齐。

## 反例或边界

- 作者未讨论 HDFS 不适合小文件、随机读写等已知限制。
- 云对象存储替代自建 HDFS 的主张涉及成本与运维对比，本集未提供数据支撑。
