# Palantir Foundry

Palantir Foundry 是 Palantir 的数据平台，承载从原始文件接入、分层存储、清洗解析到生成标准表的数据工程链路，是 Ontology 构建的上游平台。

公开可核验背景：Foundry 是 Palantir 面向企业与政府客户的商业数据集成与分析平台，与 AIP（AI 平台）配套使用；亦被概括为面向企业客户的数据集成与运营平台产品。上述产品身份为可独立核验的公开背景信息，非来源视频所提供。

本页其余产品能力与实现细节主张，均来自来源视频作者的口播解读，证据状态为 `unknown / 待外部核验`。

## 定义与定位

- 在数据工程语境下（来源：《零点未来：AI+企业/第 4 集｜14分钟揭秘Palantir一堆文件如何变成Ontology》），Foundry 被描述为“所有变换都在平台内部完成”的落点：数据从原系统拉进来时不做任何预处理，全部变换在 Foundry 内部完成，从而支持从 Ontology 任意数据点追溯到最原始文件。
- 《palantir研究/央国企一把手听懂Palantir》视频作者称，Foundry 在用户与核心数据系统之间加了一个“又安全又智能的中间层”。

## 数据工程能力（作者口播，待外部核验）

*来源：《零点未来：AI+企业/第 4 集｜14分钟揭秘Palantir一堆文件如何变成Ontology》视频。*

### 数据连接与拉取方式

- 作者称 Foundry 有 200 种连接器对接不同数据源，格式涵盖文件、PDF、PPT 甚至视频、图片。
- 作者称主要有两种拉取方式——snapshot（每次全量替换）与只追加新数据 `upam`〔待确认〕。

### 存储机制

| 机制 | 说明 |
| --- | --- |
| dataset | 通用容器，可存 CSV、JSON，每次更新有版本记录，被称 “git for data” |
| media set | 图片、视频、音频、PDF 专用存储单元，额外提供与 AI 提取工作流对接的基础 |
| media reference | 在 dataset 某一列直接引用 media set 中的文件，把结构化与非结构化数据关联起来 |

### 清洗与解析工具

| 工具 | 说明 |
| --- | --- |
| Apply Schema | 扫描 CSV 样本，自动推断数据类型 |
| Pipeline Builder | 拖拽式过滤去重，内置 AI 拆分代码能力 |
| Explode | 摊平嵌套 JSON/XML |

### 非结构化数据处理

- 由 AIP Document Intelligence 承担，见 [[aip-document-intelligence]]。

## 治理能力与“经营沙盘”定位（作者口播，待外部核验）

*来源：《palantir研究/央国企一把手听懂Palantir》视频。*

- **连接既有系统**：作者称 Foundry 能连接并利用企业所有现有的数据系统，“一个都不用换”。
- **权限与追溯**：作者称其通过“非常严密的权限管理”确保每个操作安全、可控，且“谁在什么时间干了什么都清清楚楚可以追溯”。
- **力量倍增器**：作者称 Foundry 不是推翻既有 IT 投资，而是让数据湖、ERP 等既有投资“真正发光发热”，产生“几何级数的威力”。
- **“经营沙盘”收束表述**：作者称“Palantir Foundry 的核心价值，就是为您的企业打造一个可以实时交互的经营沙盘，一个能让您看清全局、推演未来、实时指挥的作战室”。

## 已核验事实

> 本页暂无经工具直接验证的一手事实。

Foundry 作为 Palantir 商业产品的存在属公开可核验背景；但本页涉及的具体能力主张——连接器数量、拉取方式命名、存储机制细节，以及写回（write-back）能力、权限模型与审计链——均待外部核验，需对照 Palantir 官方文档查证。

## 项目分析

- Foundry 在数据工程链条中被描述为“数据工程层”，与 Ontology（语义/操作层）形成上下游关系：Foundry 负责把一堆异构文件变成干净表，Ontology 负责把干净表映射成可被 Agent 操作的对象。这一分层与 [[文件到本体的五阶段链路]] 的前四阶段对应。
- 在《palantir研究/央国企一把手听懂Palantir》的论证中，Foundry 是全片落点，承载了写回、权限、审计等具体能力主张；这些主张与 Wiki 既有 [[ontology-是操作层还是知识图谱]] 中“操作层”一方的立场一致，但证据状态为 unknown，不能作为已证实事实使用。

## 反例与边界

- “不做预处理”在技术上简单、在组织上昂贵：原始数据冗余、存储成本与平台侧合规责任都变重；当上游系统不允许原始数据出域时，该原则可能不成立。
- 作者称“不做预处理”是金融、医疗等合规行业的硬性要求，但这是作者表述，未见一手文档佐证。
- “不推翻既有 IT 投资”是典型的厂商定位式表述，落地时对既有数据湖、ERP 的改造量仍需按项目核验。
- “力量倍增器”“几何级数”属于修辞性表述，视频未给出量化依据。
- 作者把“存在一个技术上可行、权限上可控的中间层”当成已解决的问题，视频里没有给出实现细节。
