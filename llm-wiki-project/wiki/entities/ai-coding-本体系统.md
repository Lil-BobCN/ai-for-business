# AI Coding 本体系统

AI Coding 本体系统是视频作者 catface996 在《Ontology：AI Coding 在本体中的建模和实战》中演示的一套自建本体系统，用于承载 AI Coding 全流程的制品（需求、设计、任务、代码、规范、流程）及其约束。本页记录的是该来源对该系统的描述，全部规模数字与能力均属作者自述，`unknown / 待外部核验`。

## 来源描述（作者口播，`unknown`）

- 系统以 Spec 为核心组织语义建模，覆盖需求、设计、实现、测试等软件工程常规环节。
- 规模：约 70 个 class、23 个拓扑子图、25 个 command、41 条 command 依赖关系（数字前后存在不一致，见 [[queries/ai-coding本体规模数字不自洽待核验]]）。
- 通过 MCP 对外暴露，coding 工具（演示用 [[entities/opencode]]）经 MCP 接入读取本体。
- 本体上设有 `guide` 字段作为"引导区"，作者希望将其优化到一两百行，其余内容散落到各 command。
- 支持 instance 检索（目前以关键字为主，语义检索技术已支持但尚未启用）、拓扑子图检索、代码图谱化、外围操作（如 Jenkins）图谱化。
- 具备图谱健康度检测能力，包括黑洞节点、孤岛、循环依赖检测（见 [[concepts/图谱健康度检测-黑洞孤岛循环依赖]]）。
- 约束按强制力分层执行：Schema 必填 → 关系基数与拓扑 → 函数与动作 → 提示词（见 [[concepts/强制力四层排序]]）。
- 演示中实际生效的规则示例：接口协议 URL 只允许 POST 方法，格式为 `{服务}/{资源}/{操作}`（四段），五段 URL 被拒并返回引导性报错。

## 已核验事实

- 无。系统本身、规模数字、能力描述均来自作者单方面陈述，未做独立核验。

## 项目分析

该系统是本来源的演示主体，承载全部演示与数字。其规模数字不可靠，但系统本身作为"本体 + coding 工具"组合的实例具有参考价值，故建页并标注证据状态为 `unknown`。

## 反例或边界

- 作者承认渲染/生成"时间有点慢"，交互成本不为零。
- 图长大后黑洞节点需额外检测，说明遍历本身会成为问题。
- 本体成本 vs 收益未量化，小团队是否划算无判断依据（见 [[queries/本体建模成本收益边界待核验]]）。
