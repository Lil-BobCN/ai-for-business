# Spark

Spark 是一种分布式计算框架，通过把中间结果放在内存中计算来优化 MapReduce 的磁盘 I/O 瓶颈。视频作者在《第 3 集｜一口气讲透大数据、数据库、数据仓库、数据湖、数据中台的底层原理》中称其"现在已经是离线批量计算的绝对主流"。

## 定义

视频作者在该段口播中描述：Spark 针对 MapReduce 慢的问题做了核心优化——把中间结果放在内存里计算，内存不够才写磁盘，速度直接提升了上百倍。

## 来源观点

作者认为，Spark 与 MapReduce 的功能目标几乎相同，差别只在中间结果落在哪：磁盘还是内存。作者用"硬伤"来形容磁盘 I/O，并给出"提升上百倍"的结果。

## 已核验事实

无。Spark 作为 Apache Spark 项目属于公开技术事实（可独立核验的背景知识），但本集给出的"提升上百倍"为作者口播估计，`unknown / 待外部核验`。

## 项目分析

Spark 在本集叙事中承担"算"这一环节的中间站，与 [[entities/mapreduce]]、[[entities/flink]] 构成演进线。作者提出的可追问点是：内存计算的代价是什么？如果任务的数据量远大于集群内存、或者任务失败需要重算，内存化的收益还成立吗？该问题属于 [[concepts/数据移动成本视角]] 的边界。

## 反例或边界

- 作者未讨论内存化在数据量远超集群内存或任务失败重算时的收益衰减。
- 作者未讨论 Spark 在流处理场景下的定位（本集把实时场景归给 Flink）。
