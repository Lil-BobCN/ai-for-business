## 一句话摘要

视频作者认为，用 LLM 建 Ontology 已经不再是"能不能"的问题，而是"怎么建得更好"的问题：他先摆出四道坎——类型数量未知、模型幻觉、粒度难控、评估没有标准答案——再把过去两年学术界与工业界的应对归纳成五种流派（拆解派、聚类派、两步走派、框架派、直给派），并给出一条按工程复杂度与幻觉风险选型的判断框架，分界线就是"玩具"和"生产系统"。

## 主要论点

以下均为视频作者在该段口播中提出的主张，未经独立核验：

1. 没有 Ontology 时，AI 对同一问题（"供应商 A 评分"）会给出 85/92/78 等不一致答案，因为模型不知道"供应商—评分—日期"之间的关系，只是在模仿数据。
2. Ontology 是知识地图，让 AI 从"查事实"升级到"沿关系做链式推理"（材料缺货 → 产线 → 客户订单）。
3. 传统人工建模慢、贵、易过时，导致知识管理系统沦为"死档案"。
4. LLM 是解法但有四道坎：类型数量未知、幻觉、粒度难控、评估无标准答案。
5. 过去两年学术界与工业界形成五种流派，各有适用场景。
6. 选型依据工程复杂度与幻觉风险，分界线是"玩具"与"生产系统"。
7. 三条实战教训：错误集中在第一步实体提取；prompt 措辞极敏感；数据并非越多越好，关键在治理与约束合理性。

## 五种流派（作者归纳）

| 流派 | 核心思路 | 优点 | 缺点 | 适用场景 |
|------|---------|------|------|---------|
| 拆解派 | 大本体拆成小任务，每步设验证闭环 | 幻觉风险低、结果最可靠 | 工程量极大，前一步错误污染后一步 | 上生产系统 |
| 聚类派 | 先提名词、AP 聚类、LLM 命名，让数据说话 | 数据驱动、幻觉风险较低 | 聚类质量决定结果，开放域粒度易过细 | 探索全新领域 |
| 两步走派 | 先提概念清单，再整理成层次结构并序列化 | 中间产物可人工审查 | 仅适合快速出草稿 | 快速验证想法 |
| 框架派 | 基于已有框架（如 Wikidata）约束 LLM 提取 | 减少幻觉、输出天然合规 | 依赖行业已有标准 schema | 有行业标准的领域 |
| 直给派 | 端到端 prompt 直接输出本体 | 最快，半小时可出结果 | 幻觉风险最高、prompt 极度敏感 | 仅 PoC 原型验证 |

## 待核验主张清单

以下均为作者在视频中的陈述，未经独立核实：

- EDF（法国电力）用拆解派方法管理核电站的技术文档；
- 拆解派是"目前最可靠"、可以上生产系统的选择；
- `LLM for Ontology` 是 2025 年的代表性论文，其流程为"名词提取 → BERT 向量化 → AP 聚类 → LLM 命名"，并采用三步关系提取法的三元组结构；
- `Onto1kg` 这篇论文用两步走方式快速提取模块化类型并序列化生成标准 Ontology 格式；
- Wikidata 是全球最大的开放知识库、有几亿个实体；
- 去年存在一个"用 LLM 提取 Ontology"的挑战赛，且结论是 prompt 稍改就会让整个 Ontology 变掉；
- `Wingtonic`（ASR 又作 `week ontic`）用不到 1000 个 token 建立了有效的知识图谱；
- 作者自己的工具 OntoPrompt 具备置信度阈值、多文档实体验证、本体质量验证等设置，并以 DeepSeek V4 完成一次供应链本体的提取演示。

## 内部张力与边界

1. 作者称"评估没有标准答案"（第四道坎），却又主张拆解派"结果最好"、可上生产——若无可比口径，"最好"缺乏依据。
2. 双重验证的规则由谁写？若规则也来自 LLM 推断，闭环可能沦为自证（作者未说明）。
3. 流派边界模糊：直给派加约束即含拆解派成分，OntoPrompt 本身即混合体，五分类并非互斥。
4. 效果证据均为单点案例式叙述，无对照组、无度量口径。
