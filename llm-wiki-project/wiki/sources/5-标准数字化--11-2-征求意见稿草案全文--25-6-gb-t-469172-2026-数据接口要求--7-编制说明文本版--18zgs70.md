## 三、标准制定背景（起草组自述）

起草组以《国家标准化发展纲要》“发展机器可读标准、开源标准，推动标准化工作向数字化、网络化、智能化转型”为政策依据，提出：机器可读标准分级模型中，智慧标准需要赋有语义并支撑 ISO/IEC 机器可读可执行；实现标准机器可读、可执行、可解析的重要渠道就是标准语义知识库的数据接口。

起草组列举四类现存问题：

1. **标准使用仍以“人类阅读使用”为主**，未能为各类系统和设备所调用，标准未能充分实现“机器可读可理解”。举例：许多组织、企业已建设标准知识库（如国家标准馆），但在标准语义要素的利用上仍较为缺乏。
2. **标准与产业链应用交互困难**，上下游标准不同步导致产业总体成本居高不下。举例：电网和设计院、船厂和设计院均未有统一标准知识库接口。
3. **各层级、各领域标准数据存在孤岛、难以融合应用**。举例：电网基建工程设计除电力行业和电网自身标准外，还需参考土建等方面标准，而设计单位掌握的土建、城市规划标准往往比电网企业更齐全。
4. **多领域均在建设标准知识库相关接口，但仍未形成统一规范**。举例：南方电网在企业内部构建标准语义知识库并构建“标准中台”（标准语义要素相关服务接口），提供给电网设备全生命周期管理使用；航空、船舶等头部企业也建设了标准知识库并通过接口开放至设计、检修等业务使用。

> 以上均为起草组定性论述与举例，**无量化数据**，证据状态 `unknown`。

## 四、起草过程时间线

起草工作组由**南网科研院、中国标准化研究院、华南理工大学**等产、学、研单位组成。

资料收集与行业调研涉及文件：

- 《信息技术 大数据 接口基本要求》（GB/T 38672-2020）
- 《全国一体化政务大数据体系共享服务数据交换要求》标准草案
- 《Industrial automation systems and integration — Product data representation and exchange — Part 22: Implementation methods: Standard data access interface》（ISO 10303-22）

调研领域：电网、船舶制造、航空等领域的标准知识库接口设计方法、应用模式。

## 五、编制原则

本文件编制主要遵循**协调性、易用性和实用性**三项原则：

- **协调性**：接口设计要求严格遵循系列标准第 1 部分《标准语义知识库 第1部分：标准内容语义化表达通用要求》相关要求，确保数据结构、类型与知识库本体一致，同时兼容 JSON-LD 等国际标准及通用协议，支持各行业本体的灵活集成，实现跨系统数据交互的全局协调。
- **易用性**：采用成熟的 RESTful API 与 JSON Schema 技术方案，降低企业开发门槛，可快速融入企业研发流程，降低知识库建设方与接口应用方成本。
- **实用性**：基于产业企业、科研单位、高校等多个单位共同研讨、编制，满足多行业、多领域开发与调用，可有效解决标准内容语义化表达单元交互难、流通难的问题。

> 原文“第部分”“JSON-LD”处存在文本错位，属还原瑕疵。

## 六、标准的主要内容（六项）

1. **数据接口建设与应用原则**：遵循通用性、实用性、安全性与可用性原则，要求接口兼容多层级标准及主流系统，设计以业务需求为导向，采用加密、认证机制保障数据安全，支持高负载与异常条件下的稳定运行。
2. **数据接口总体框架**：基于数据供给方、数据库建设方、数据调用方的三方协作架构，分层设计数据接口、功能接口与服务接口，规范标准语义化要素的传输、基础功能调用及微服务嵌入，实现数据交互与业务解耦。
3. **接口通信方式要求**：支持 HTTP/HTTPS 协议及双向认证，采用请求模式（同步/异步调用）与推送模式（订阅更新）实现双向交互，通过 RESTful API 提供标准化 Web 服务，以 JSON/XML 格式结构化传输语义化要素。
4. **基础接口要求**：定义要素查询、订阅、推送、转换接口，支持按标准号、名称、要素类型精准检索，动态订阅更新，结构化数据推送，要素格式转换（图谱、向量）及关联关系溯源，满足基础数据交互需求。
5. **高级接口要求**：提供标准比对、问答与推荐接口，基于语义化要素抽取与智能算法，实现跨版本差异分析、自然语言问答及关联知识推荐，支撑一致性验证、智能检索与知识扩展等场景化应用。
6. **接口管理要求**：建立接入授权、日志审计与版本控制机制，通过通用算法实现细粒度权限管控，记录全链路操作日志并定期审计，明确接口版本标识与兼容性规则，支持故障回滚与数据一致性校验，确保接口规范化运行与安全性。

## 七、主要内容的确定依据

1. **文献参考**：在接口的设计方法和设计思想上，充分借鉴《Details of the Asset Administration Shell》《信息技术 大数据 接口基本要求》，提出包含接口出入参、接口说明的同时兼顾通用与实操性的接口设计逻辑；同时基于系列标准的第 1 部分，建立具有标准文本特点的接口协议，具有较强的针对性。
2. **调研与讨论**：起草工作组在标准资源提供组织、出版单位等领域和电力、船舶等行业充分调研，研讨形成标准主要内容，主要的接口协议、管理方式均为各个行业实践的成果。

## 八、效益论证（起草组预期，未测算）

- **经济效益**：通过统一标准语义知识库数据接口的规范与技术推广，提升研发与对接效率，降低企业研发成本及系统接入成本；规模化推广后整体产业链的研发与对接成本呈现集约化节约效应。
- **社会效益**：规范数据接口供给与使用，打通全产业链数据协同链路，推动上下游标准应用统一化与规范化，为构建全国统一大市场提供技术基础；作为数字化转型核心基础设施，加速标准数据高效流通。

> 均为定性预期，**无测算数据**，证据状态 `unknown`。

## 九、与国内外标准的关系（第六章）

| 对比对象 | 关系说明 |
| --- | --- |
| ISO 10303-22:1998 | 对象、领域不同：描述工业等领域的标准数据接口，非标准文件的数据接口 |
| GB/T 38672-2020《信息技术 大数据 接口基本要求》 | 描述对象不同，在接口的框架上有参考 |
| 《全国一体化政务大数据体系共享服务数据交换要求》（正在审查） | 不属于同一领域，但在标准语义知识库协议上有参考借鉴 |

| DB4401/T 223-2023、DB4403/T 313-2023 等地方标准 | 领域不同：地标主要对象是教育数据、智慧停车数据等，暂无标准数据相关地标 |

**国际对比主张**：“当前暂无国际标准及国外相关标准开展标准语义知识库数据接口的要求，国内标准数字化相关标准提前布局，目前在国际处于领先水平。”

> 该主张属起草组判断，证据状态 `unknown`，与既有 [[queries/标准数字化标准族国际标准一致性程度待核验]] 存在张力。

**以国际标准为基础的起草情况**：由于尚未发布相应国际标准，该文件没有以国际标准化文件为基础起草，且没有引用国际国外标准。
