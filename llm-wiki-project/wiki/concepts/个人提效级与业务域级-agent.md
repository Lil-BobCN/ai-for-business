# 个人提效级与业务域级 Agent

个人提效级与业务域级 Agent 是视频作者在《第 6 集｜6分钟聊聊本体Ontology和Agent那些事》中提出的一个层级区分，用来界定多数企业当前的 Agent 现状与真正的落地门槛。

## 定义（来源观点）

- **个人提效级 Agent**：让个人更快，但没有改动业务对象本身。作者举例：飞书 Aily、飞书多维表格、财务对账提效、写周报、写 PPT 的 Agent Skill；稍复杂者用 Dify 等开源工具搭建 workflow（如监听邮件服务器、下载附件、解析后由 Agent 填写到系统）。
- **业务域级 Agent**：直接参与深度业务领域，做成体系化的结果，需要业务域级别的本体与 Agent 运行体系支撑。

作者称，目前很多企业都在上 Agent，但说白了还是个人提效级别为主，大多数企业并没有让 Agent 直接参与到深度的业务领域。

## 门槛（来源观点）

作者认为其中一个很大的原因是公司的 1 号位不知道要做，或不知道怎么做、没有感知去建本体、搭建业务域级别的本体和 Agent 应用。要先让 1 号位理解这个东西有什么用，才可能拉动公司业务域级别的实际落地。

## 已核验事实

无。本页内容均来自视频作者口播观察，未经独立核验。

## 项目分析

- 作者列出的工具与场景（对账、周报、PPT、邮件附件解析）恰好都在同一层级：它们让个人更快，但没有改动业务对象本身。
- 门槛不在工具能力，而在于有没有人愿意为"业务语义"这件事负责。
- 可迁移的追问：一个从个人提效长出来的 Agent，要补上什么才算进入业务域级别？

## 反例或边界

- 对流程本就简单的中小企业，"个人提效级 Agent + Skill"可能不是落后形态，而是长期合理形态。
- 作者把"跟风"归因于认知不足，可能低估了组织里"先上车再补定义"的现实动机。
