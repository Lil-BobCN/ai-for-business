# 上下文压缩

## 定义

视频作者在该段口播中提出：上下文压缩（context compression）指当一次 session 接近 context limit（上下文上限）时，运行时自动压缩前面的上下文，同时尽可能保留后续继续工作需要的信息，使一个任务可以跨多个 context window 继续执行。

## 来源观点

作者称，以前程序员经常需要自己实现 summary memory 或 checkpoint；有了 Agent API 之后，上下文压缩被做进了运行时（ASR 作 `Honest`）里面。作者提到，用过 Claude Code 以及 `collects`〔ASR 原文，所指待确认〕的人都会遇到上下文压缩的情况。作者由此判断：Agent 真正从短对话走向了连续工作几个小时，上下文管理也越来越像标准基础设施，而不是每个团队都要重新打造一遍。

## 已核验事实

无。机制描述来自作者口播，属 `unknown / 待外部核验`。

## 项目分析

「压缩」本身不是难点，难点是「哪些信息不能丢」。作者讲清了机制，但没有说明这个取舍由谁定规则。若被压掉的是某次审批的依据、某个口径或某条例外条件，事后能否还原，会从效率问题变成合规问题，见 [[queries/上下文压缩的合规边界待核验]]。

## 反例或边界

- 作者未说明压缩策略是否可配置、是否可按业务规则定制。
- 示例集中在工程排障场景，长审批链业务场景未检验。
