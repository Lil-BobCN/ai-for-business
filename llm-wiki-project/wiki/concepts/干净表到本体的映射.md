# 干净表到本体的映射

"干净表到本体的映射"是本来源视频作者给出的对应关系：把清洗后的标准表逐列映射成 Ontology 的 Object Type、Object Entity、Property、Link Type 与 Action Type。本页内容属作者口播观点，`unknown / 待外部核验`。

## 定义

| 关系型结构 | Ontology 元素 | 示例 |
|---|---|---|
| 一张干净表 | Object Type | 航班表 |
| 表里每一行 | Object Entity | 航班号 CA1234 |
| 表里每一列 | Property | 出发时间、状态 |
| 两张表之间的关联 | Link Type | Flight 通过尾号关联 Aircraft |
| 数据读写操作 | Action Type | 改签、更新状态 |

## 来源观点

作者强调 Action Type 是 Ontology 的核心：传统数据目录只能查不能改，而 Palantir 的 Ontology 让业务用户也能直接修改数据，改动写入独立 writeback dataset，不污染原始数据。

## 已核验事实

本页暂无经工具直接验证的事实。

## 项目分析

这套映射把"语义层"从抽象概念落到列级对应关系，是 [[本体schema与实例事实]] 与 [[本体建模业务定义数据映射与关系校验]] 的工程补充。其中 Action Type 与 writeback 机制可延伸 [[工具调用]] 页面。

## 反例与边界

- 映射前提是"业务实体与字段归属存在稳定且可判定的答案"；若企业内部对"什么算一个订单"本身有分歧，映射会更贵。
- 一个 Object Type 只能对应一张表，因此宽表必须先拆再映射，见 [[宽表拆分规则]]。
