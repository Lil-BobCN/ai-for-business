# 接口返回状态码

## 定义

接口返回状态码是标准语义知识库数据接口在响应请求时返回的状态参数，用于标识接口调用的结果状态。在《标准语义知识库 第 2 部分：数据接口要求》（征求意见稿）第 9 章中，规定接口返回状态参数应包含特定条件和参数，如开发过程中有新增条件和参数的，参数值应满足 HTTP 协议的要求。

## 来源观点

来源（征求意见稿第 9 章）给出的状态码表如下（原文标题为“表 9 stdStatusPush 请求返回参数”，但正文称“表11”，存在编号不一致）：

| 参数 | 条件 |
|------|------|
| 200 | 请求成功，接口调用正常、且可返回正常的标准通用及专用语义化要素数据 |
| 204 | 请求成功，接口调用正常，但由于请求的标准通用及专用语义化要素在标准语义知识库中不存在的情况 |
| 206 | 请求部分成功，如对标准的各级体例进行设置时，仅部分层级成功 |
| 401 | 请求未被授权，如请求的用户未在标准语义知识库接口管理服务中注册、用户越权访问了在业务允许范围之外的标准通用及专用语义化要素等情况 |
| 404 | 接口部署相关服务器连接正常，但未正确请求接口，出现服务端找不到相关接口的情况 |
| 500 | 服务器内部错误，一般为临时出现 |

## 已核验事实

无。本页内容全部来自征求意见稿文本，尚未发布，属未核验状态。

## 项目分析

状态码语义基本沿用 HTTP 标准语义（200 成功、204 无内容、206 部分内容、401 未授权、404 未找到、500 服务器内部错误），但结合标准语义知识库场景做了具体化解释，例如 204 被解释为“请求的标准通用及专用语义化要素在标准语义知识库中不存在”，206 被解释为“对标准的各级体例进行设置时，仅部分层级成功”。

## 反例或边界

- 表号不一致：正文称“表11”，实际表格标题为“表 9”。见 queries/状态码表编号表11与表9不一致待核验。
- 状态码表标题为“stdStatusPush 请求返回参数”，但正文表述为通用“接口返回状态参数”，二者适用范围是否一致待核验。
