# 五个工作流设计模式

本页记录「零点未来」第 8 集视频作者拆解的五个工作流（workflow）设计模式。作者把它们定位为自主性阶梯的低段：固定流程、预先定义好的内容，缺乏足够的自主性。

## 定义与适用场景（来源观点，`unknown / 待外部核验`）

### 1. Prompt Chaining（提示链）

把任务拆解成一串固定的步骤，每一步处理上一步的输出，就像工厂的流水线。好处是每一步的错误不会滚雪球，因为每一步都要被检查一遍。作者总结：提示链把每个 LLM 调用变成一件更小的任务，用延迟来换准确率。

### 2. Routing（路由）

像一个智能交换机，LLM 给输入做分类，然后送进最合适的通道——简单的小问题给小模型，这样省钱；难题就给推理模型。作者类比医院的分诊台护士，不治病，只判断你该挂哪个科。

### 3. Parallelization（并行化）

多个 LLM 同时干活，然后再汇总结果。作者给出两种形态：

- **切分**：把独立的子任务拆开并行跑；
- **投票**：同一个任务跑多次，然后取多数。

作者补充：复杂任务交给单一的 LLM 一次性处理，效果通常不如拆开、让多个 LLM 各自负责一块。

### 4. Evaluator-Optimizer（评估与优化）

一个生成器（Generator）产出输出，加上一个评估器（Evaluator），构成一个简单的小循环，直到评估通过、或者最大的迭代次数到了就停下来。作者强调：给到评估器的评估标准必须清晰可见——如果标准含糊，这个循环就会原地打转，甚至越改越糟。

### 5. 编排〔英文模式名 ASR 未捕获，待确认〕

一个编排者进行任务的动态拆解，然后派给具体的「功能」〔ASR 原文如此，所指待确认〕，再把这些结果合成在一起。作者说，它跟并行化的区别就在于：任务不是预先定义好的，是编排者根据具体的输入现场决定的。

## 项目分析

- 五个模式构成一条从「完全写死」到「现场动态拆解」的连续谱，与 [[concepts/workflow与agent的分界]] 的判据一致。
- 作者在收尾的「组合」原则中提出：在确定的 Prompt Chaining 里把某一步换成 Agent 动态调 API，常比整体升级划算——即工作流模式与 Agent 模式可混合使用。

## 反例或边界

- Evaluator-Optimizer 的前提是「评估标准清晰可见」，但在开放域任务（写作、策略判断）中，标准本身往往就是要产出的东西，此时循环容易空转甚至越改越糟，作者未讨论这一边界。
- 并行化的两种形态（切分、投票）与 Anthropic 原文中 Sectioning / Voting 的对应关系待核验。
- 编排模式是否即 Anthropic 体系中的 Orchestrator-Workers 待核验。
