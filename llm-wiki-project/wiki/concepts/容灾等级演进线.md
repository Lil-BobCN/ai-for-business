# 容灾等级演进线

容灾等级演进线是把容灾方案按可用性档位从低到高排列的一条分级视角，本页依据视频作者在该段口播中给出的六级方案整理：同城冷备 → 同城热备 → 同城双活 → 两地三中心 → 异地双活 → 异地多活。每一级都在解决上一级遗留的问题，并以 RTO／RPO 作为判据。

## 来源观点（视频作者口播主张，`unknown / 待外部核验`）

- **同城冷备**：同城另一机房部署同套系统，定时备份，故障时手动启动并切域名。RTO 小时级，作者称仅用于测试环境。
- **同城热备**：备机房应用与数据库常驻运行，主备集群实时同步，故障时主备切换。RTO 分钟级，RPO 很小。作者补充同城冷备与同城热备都属于同城容灾。
- **同城双活**：流量入口增加调度层（动态域名解析或负载均衡器），按比例分流并自动探测健康状态；写操作发主机房主库、读操作就近读本机房从库。RTO 分钟级。
- **两地三中心**：城市 B 机房 C 实时备份城市 A 数据（异地灾备），并定期切换部分生产流量做容灾演练，应对城市级灾难。
- **异地双活**：跨城专线延迟成为硬约束；解法为双向同步 + 应用层路由隔离，同一用户只落一个机房；全局强一致数据仍走"写主读从"。
- **异地多活**：多地域部署，设中心机房做星形同步以降低链路复杂度，中心机房需可重选。

## 已核验事实

本页暂无独立核验事实。各级方案的 RTO／RPO 区间与延迟数字均为作者讲解用量级估计。

## 项目分析

这条演进线同时是一条成本线：机房数量、专线、同步中间件、路由改造、跨机房联调，都是随级别上升的固定投入。可延展方向是为容灾等级建立一张分级表——每一级写清能扛哪种故障、RTO／RPO 的典型区间、需要多少额外成本，让"要不要上异地双活"变成可比较的问题而不是立场之争。

## 反例或边界

- 隐含前提：容灾等级可线性升级；现实中机房选址、专线采购、合规要求常先于架构确定。
- 反方向：也可把 RTO／RPO 谈低、用更简单方案满足业务，而非持续加机房。
- 来源未讨论成本结构，也未给出真实切换复盘数据。
