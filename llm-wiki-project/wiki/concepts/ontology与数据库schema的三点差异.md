# Ontology 与数据库 Schema 的三点差异

"Ontology 与数据库 Schema 的三点差异"是本来源视频作者用来定性 Palantir Ontology 的框架：全链路可追溯、可写回、应用层直接消费。作者认为三点合起来使 Ontology 成为"Agent 的操作层"，而非数据结构目录。本页内容属作者口播观点，`unknown / 待外部核验`。

## 定义

1. **全链路可追溯**：Ontology 里任意字段值可追溯到原始文件（作者表述为"某一行"，扫描件场景实际对应某一页）。
2. **可写回**：Action 修改写入 writeback dataset，不污染原始数据。
3. **应用层直接消费**：无需再写 API，AI 与应用直接操作 Ontology 对象，可做业务决策与仿真。

## 来源观点

作者认为这三点合起来，使 Ontology 成为"Agent 的操作层"，而不只是一个数据结构目录。这一点把第 1 集"语义层"的说法落到了工程细节。

## 已核验事实

本页暂无经工具直接验证的事实。

## 项目分析

只读的语义层和可写的语义层在治理上是两回事：前者出错大不了看错，后者出错会改坏业务数据。作者强调改动要写进独立的 writeback dataset，本质是给"可写"这件事加了一层隔离。这与 [[本体作为约束层]] 互补——约束层管"能做什么"，可写回管"改了之后去哪"。

## 反例与边界

- writeback 记录与原始数据长期分叉之后，哪一份才是业务上认可的"真相"，作者未回答。
- "追溯到原始文件的某一行"在扫描件场景不成立，实际对应某一页。
