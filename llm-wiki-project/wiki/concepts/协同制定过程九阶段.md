# 协同制定过程九阶段

## 定义

协同制定过程九阶段是 GB/T 48000.4-2026《标准数字化 第4部分：协同制定要求》（征求意见稿）第7章提出的标准协同制定过程框架，指标准协同制定过程应按照 GB/T 1.4 进行系统规划，主要包括**预备、立项、起草、征求意见、技术审查、批准发布、出版、复审和废止**等阶段，以便实现标准生命周期的协同。

## 来源观点

以下内容来自本文件第7章（证据状态 `partial`，草案未生效）：

- 7.1 概述：不同层级的标准制定过程会有所不同，根据具体实际，可省略 7.2-7.10 中的某些阶段，但是为了满足协同制定的要求，各阶段需要实现的协同事项是一致的。
- 各阶段均以"某角色应通过标准数字化平台……"的句式规定该角色在平台上的具体任务，形成"阶段 × 角色"的任务矩阵（见附录A 表A.1）。
- 阶段与文档状态流转对应：PWI/ID/NP（预备、立项）→ WD（起草）→ CD（征求意见）→ DS（技术审查）→ FDS（批准发布）→ PDS（出版）。

### 各阶段要点

| 阶段 | 主要角色 | 关键任务 |
| --- | --- | --- |
| 7.2 预备 | 建议方、TC、委员 | PWI/ID/NP 在线编写与提交；TC 形式审查、自动生成 PWI 投票；委员在线投票 |
| 7.3 立项 | 标准机构、立项评估专家、TC | 分类管理、匹配立项评估专家、初核 NP/ID、专家立项评估、公开征求意见、下达项目计划 |
| 7.4 起草 | TC、WG组长、起草者、专家 | 创建起草任务并授权；任务分解；WD 研讨；WD 最终稿登记为 CD |
| 7.5 征求意见 | TC、委员、意见提出者、WG组长、起草者 | CD 推送与在线评议；意见处理；CD 登记为 DS |
| 7.6 技术审查 | TC、委员、WG组长、起草者 | DS 分发与审查会；DS 投票；形成 FDS 并提交标准机构 |
| 7.7 批准发布 | 标准机构 | 审核 FDS 齐全性/形式符合性/协调性/程序合规性；登记为 PDS；赋号、批准发布 |
| 7.8 出版 | 标准出版机构 | 格式校验、编辑加工，以纸质/PDF/HTML/XML/数据库/软件程序/访问接口等形式出版发行 |
| 7.9 复审 | TC、复审专家、委员 | 收集需求变更与实施反馈；专家复审；委员投票；形成复审报告 |
| 7.10 废止 | 标准机构、意见提出者、TC | 发起废止公开征求意见；形成处理意见；发起废止流程；TC 维护归口标准信息 |

## 项目分析

- 九阶段框架与现有 [[concepts/生命周期四阶段]] 是**不同框架**：后者来自 GB/T 48000.2 参考架构模型，粒度与用途不同。两者关系待核验（见开放问题）。
- 九阶段与 GB/T 1.4 的标准制定程序存在对应关系，但本文件将其置于"标准数字化平台支持"的语境下，强调各阶段通过平台完成的协同事项。

## 反例或边界
