# Code First 升级阶梯与 L0–L4 成熟度模型

## 定义

Code First 升级阶梯与 L0–L4 成熟度模型，是视频作者提出的企业 AI 选型路径与分级框架：从简到繁、不够再加，依次为 Code First → 一次 LLM 调用 → Workflow → 受约束的 Agent → 自主的 Agent，并对应成 L0–L4 五级架构成熟度模型。

## 来源观点

视频作者在该段口播中提出（`unknown / 待外部核验`）：

- **五个步骤**：能写成具体规则 → Function；只做一次分类或抽取生成 → 单次 LLM；步骤能详细列出 → Workflow；连下一步都无法确定 → 才上 Agent；影响大、不可逆 → 要能人工把关。
- **升级阶梯**：Code First（代码优先）→ 一次 LLM 调用 → Workflow → 受约束的 Agent → 自主的 Agent。
- **决策矩阵**：Function 最便宜、最稳；Agent 最灵活、最贵，风险也最大。

五级架构成熟度模型（按原文保留）：

| 级别 | 名称 | 说明 |
|---|---|---|
| L0 | 纯计算（Function） | 输入输出恒定 |
| L1 | 单次 LLM | 一次分类/抽取/生成 |
| L2 | LLM Workflow | 多数企业默认选择 |
| L3 | bounded agent | 固定工具范围、预算内动态规划 |
| L4 | autonomous agent | 自主规划 |

| 路线 | 成本 | 稳定性 | 灵活性 | 风险 |
|---|---|---|---|---|
| Function | 最低 | 最高 | 最低 | 最低 |
| Agent | 最高 | 最低 | 最高 | 最高 |

作者特别提醒，这不是一个「越往上越牛」的竞赛。L0 到 L3 能够共存：Function 兜底，Workflow 走主线，Agent 只处理少量、搞不开的局部流程。他给出的判断是，多数企业其实把 L2 做深就可以了。

## 已核验事实

无。本页内容全部来自视频作者口播，尚无一手资料或独立核验支持。L0–L4 五级模型是否为作者自创或引用待核验。

## 项目分析

把成熟度模型读成「升级路线图」，很容易得出「迟早要上 L4」的结论；作者的原意恰好相反——每一级都有自己的适用范围，停在 L2 是一个结论，不是一个过渡状态。可延展方向：给每一级配一个明确的退出条件（比如例外率、接管率、人工介入时长），让升级变成一次有依据的判断而不是一次冲动。

## 反例或边界

- 「接管率、失败样例」被当作升级依据，但高接管率既可能是 Agent 能力不足，也可能是上游数据口径问题的症状；若为后者，升级架构正好绕过真正该修的地方。作者未区分。
