# 生产级 Agent 五件事

本页记录「零点未来」第 8 集视频作者提出的生产级 Agent 设计必须考虑的五件事。作者把它们定位为各种模式进入生产的准入条件。

## 五件事（来源观点，`unknown / 待外部核验`）

### 1. 记忆和检索

RAG 解决知识够不够的问题——够不够新、够不够专；长期记忆则解决记不记得你是谁、之前聊了什么、之前做过什么样的决策。

### 2. 护栏

在企业里面落地 AI Agent，一定要考虑安全权限的问题，要设置规则的护栏，还有安全的权限审核。作者补充：如果没有这些护栏，Agent 不能够用在生产环境里面，企业用起来也有风险。

### 3. 人在回路

作者给出两种触发机制：

- 超过失败的阈值，比如重试了多次还没有搞清楚，就要升级为人工；
- 高风险的操作，比如取消订单、大额退款、付款这种，就需要人工参与。

### 5. 可观测性设计

需要保留日志，多个 Agent 的调试〔ASR 作「调色」，所指待确认〕都要靠日志来进行留痕，才可以进行审计。

## 项目分析

- 本页与 Wiki 既有 [[concepts/防幻觉的架构化机制]]、[[concepts/action分级与确认机制]] 主题相关，但本集是另一套划分（通用 Agent 工程视角），应并列而非合并。
- 作者补充：现实中的 AI Agent 系统设计其实都是混合在一起的，都是一个混合模式设计，有可能是一个简单的模式加一个复杂的模式混合在一起。

## 反例或边界

- 人在回路的两条触发机制都依赖事先定义，事前无法枚举的高风险动作仍会漏网。
- 高风险名单写得过宽会把人工通道变成瓶颈，反而把团队推回「全自动」那一侧。
- 可延展方向：把触发条件写进配置而不是代码，让业务方能自己调整失败阈值和高风险清单。
