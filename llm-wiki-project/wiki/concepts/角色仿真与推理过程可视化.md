# 角色仿真与推理过程可视化

## 定义

角色仿真与推理过程可视化是视频作者零点未来在「AI+企业」第 5 集 demo 中展示的两项功能：角色仿真用于对比不同方案的 performance 与 metrics，推理过程可视化用于展示 Agent 在交互中调用了哪些工具、查了哪些本体、算了哪些函数。

## 来源观点

以下均为视频作者在该段口播中提出的观点，属 `unknown / 待外部核验`。

- **角色仿真**：可对比不同方案，查看不同方案的 performance 与 metrics。示例中系统查询所有订单情况，返回 12 个订单总览，标注高风险订单，其中两个已延误、风险评分达到 100%；针对这两个警戒订单询问建议与角色仿真对比，系统建议两个都更换承运商，给出延误时长缩短多少、额外成本增加多少，并给出综合建议与客户主动沟通建议。
- **推理过程**：展示调用了哪些工具与本体交互——上下文创建（加入哪些上下文给 LLM）、调用 Query Tool 查询本体（Customer、Order、Shipment、Carrier，此处 ASR 另有一个词作 `google`，所指待确认）、调用哪些函数、角色仿真模拟。

作者认为这是「比较具象化的、实际对业务决策能够产生价值的例子」。

## 已核验事实

暂无。本页内容全部来自单一视频作者口播，本地 ASR 为 `partial`。

## 项目分析

- 角色仿真的价值在于「可重算的差值」：决策者拿到的不是一条结论，而是几套方案之间的差值，可被反复重算。
- 推理过程可视化把抽象架构落成可见交互，是决策工具层面的可迁移素材。
- 与 [[concepts/业务验收指标口径]] 相关：仿真输出的 metrics 需要明确口径才能被验收。

## 反例或边界

- 仿真数字来源不明：demo 中「延误缩短多少、成本增加多少」未说明来自历史回归、规则推算还是模型估计，缺少对照就无法判断可信度。
- demo 数字（12 个订单、2 个高风险、风险评分 100%）未经核验。
- 作者未说明当仿真给出的最优方案需要额外成本时，成本与时效的权重由谁设定、系统如何记录该权重。
