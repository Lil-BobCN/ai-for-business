# 本体 Schema 与实例事实

本体 Schema 与实例事实是视频作者用于讲解本体的两个层次：Schema 描述领域中的类型、属性和关系，实例事实描述具体对象及其关系。本页记录作者的框架并补充分析，不将其视为已经核验的唯一或普遍分类。

## 来源观点

视频作者称，Schema 定义 `Objects`、`Properties` 和 `Links`，例如声明学生和课程两类对象，以及学生可以选修课程的关系。实例事实则记录某个具体学生选修了哪门课程。

作者提到 OWL 可用于表达模型定义和实例事实，并以 `Class`、`DataProperty`、`ObjectProperty` 说明类型、数据属性和对象关系。该术语映射及 OWL 的能力边界见 [[OWL]]，尚待独立核验。

## 当前分析

Schema 描述允许表达什么，实例事实描述某个业务对象或关系的具体状态。工程中还需要识别对象的稳定身份；仅凭姓名等易重复属性连接对象，可能造成关系错接。视频作者以姓名重名和工号为例解释这一点，但没有给出身份治理方案或真实数据验证。

当 Schema 中的对象类型与数据中的表示不一致时，例如模型声明课程对象而来源系统只提供课程名称文本，如何清洗、映射或修改模型仍需按具体数据和业务口径判断。不能仅凭本集决定应先改 Schema 还是事实数据，相关问题见 [[本体与数据约束及版本演化待核验]]。

## 边界

- Schema 与实例事实的区分可用于整理建模讨论，但不意味着所有业务数据都能简单映射为对象、属性和关系。
- 实例事实变化不必然代表 Schema 变化；对象类型、属性含义或关系规则变更则可能涉及模型演化。
- 声明关系不等同于数据已经符合关系定义，也不等同于系统已经执行校验或推理。
- 本集没有给出可直接复用的 Schema 文件、字段定义、身份规则或映射配置。
