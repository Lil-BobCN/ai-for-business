# Workflow 与 Agent 的分界

本页记录「零点未来」第 8 集视频作者提出的 workflow 与 agent 分界判据。该判据是全集立论的起点，也是选型的第一判据。

## 定义（来源观点，`unknown / 待外部核验`）

视频作者在该段口播中提出，workflow（工作流）与 agent（智能体）是两回事，分界在于**「谁决定下一步」**：

- **workflow**：LLM 被编排在预先写死的代码路径里，流程固定，模型只在每一步里面去干活，不能决定下一步。
- **agent**：LLM 动态决定自己的执行过程，每一步用什么工具、要不要继续，都是模型现场决策。

## 来源给出的对照例

- **workflow 例：RAG**——先检索、再拼提示词、再生成，顺序写死，模型说的不算。
- **agent 例：客服退货 Agent**——用户说「我想退货」，没有固定脚本，Agent 自己决定先调用工具查订单，再核对退货政策，判断在不在窗口期内，最后才执行退款。

## 相关二分：LLM 是模型，Agent 是系统

作者在同一集中提出另一对区分：本质上 LLM 是模型，Agent 是系统，区别不在于聪明的程度，而在于**有没有行动的闭环**。

- LLM 会说话但不会干活：不调用工具、不查数据、没有记忆，也不能行动。问它「我的订单到哪了」，它只能基于训练数据猜一个答案。
- Agent 会干活、完成任务闭环：同一个问题，Agent 会调用查询订单的工具拿到真实订单，再调物流工具查实际状态。

## 项目分析

- 「谁决定下一步」这一判据把「要不要上 Agent」的问题转化为「哪一步交给模型决策」的步骤题，与作者收尾的「组合」原则一致。
- 该判据与 Wiki 既有 [[concepts/工作流与人工介入]] 可能存在定义口径差异：既有页可能把含人工节点的编排也归入 workflow，而本集把 workflow 限定为「LLM 被编排在写死的代码路径里」。若构成冲突，应保留双方来源。

## 反例或边界

- 作者把 Agent 的能力标价为「更高的延迟和成本换更好的任务表现」，因此分界判据之外还需一个采购式判断：这一步的自主决策能换来多少任务表现。
- 若某环节失败代价低、结果又容易验证，「让模型自己决定」买到的收益可能有限。
