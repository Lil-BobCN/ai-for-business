# 本体三要素：对象、属性与关系

本体三要素指 objects（对象）、properties（属性）、links（关系），是视频作者在本集中给出的最小本体建模框架：用对象描述业务中的具体事物，用属性描述对象的特征与状态，用关系描述对象之间的关联，从而把散落的异构数据组织成共同的业务模型。

## 定义

- **objects（对象）**：描述业务中正在处理的具体事物。作者举例：客户是一个对象，可以是张三、李四、王五；订单是一个对象，可以是 1042、1045、1046。
- **properties（属性）**：对象具有的特征与状态。作者举例：客户有姓名、年龄、居住地；订单有下单时间。
- **links（关系）**：对象之间的相互关联。作者举例：客户与订单之间是「下单」关系；订单与主机、奶泡壶之间是「关联」关系；主机与物流之间是「签收 / 运输」关系。

## 来源观点

- 视频作者在该段口播中提出：ontology 核心就是用 objects、properties、links 这三个概念，把分散的信息组成一个共同的业务模型，为 Agent 提供上下文信息。
- 作者用一张电商关系网演示三要素的落地形态：客户（张三、礼眉〔待确认〕）→ 订单（2068、1042）→ 订单明细 → 商品（咖啡机、奶泡壶等），并称「看起来有点像知识图谱」。

## 已核验事实

- 本集未提供任何实测数据、对照实验或第三方文档来验证该三要素框架的完备性，全部为作者口播主张。

## 项目分析

- 三要素是本集最可操作的部分，可作为最小建模模板：把一份数据字典改写成「品类名（对象）/ 字段（属性）/ 外键语义（关系）」三列，即得到一份本体草案。
- 该框架与既有 [[concepts/本体schema与实例事实]] 的分层思路一致：对象与属性偏 schema 层，具体实例（张三、订单 1042）偏实例事实层。
- 与 [[concepts/本体建模业务定义数据映射与关系校验]] 相比，本集更强调「三要素」这一最小切分，而非建模流程本身。

## 反例或边界

- 作者未回答三要素中哪一个最容易在客户现场出问题：对象边界划不清、属性口径不统一，还是关系类型定义不完备。
- 三要素本身很朴素，真正的难点落在「谁来决定哪些对象该被建出来」，本集未展开。
