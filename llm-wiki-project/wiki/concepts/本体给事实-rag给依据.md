# 本体给事实、RAG 给依据

## 定义

"本体给事实、RAG 给依据"是视频作者木羽Cheney 在第 12 集口播中提出的分工口径：本体提供建模后的确定事实（对象、属性、关系、业务规则），RAG 补上这些事实的原文出处（原本片段、原本出处）。两者共同构成 Agent 回复时使用的上下文。

## 来源观点

视频作者在该段口播中提出：

- 本体里主要存储的是从散落文档中按 Schema 抽取出来的对象，以及对象之间的 link 与关系，因此可以查询出事实。
- 但每个对象可能来源于某一个文件、某一个链路，还带有额外的非结构化信息。
- 因此要追到"原本的片段、原本的出处"，往往需要结合 RAG 来共同构成回复的上下文。
- 演示界面「核对结果明细」中出现的规范原文与文件页码，被作者用作"这一部分是基于 RAG 做的增强"的证据。

## 已核验事实

无。本页内容全部来自视频作者单方口播陈述，未经独立核验。

## 项目分析

- 该分工把"要不要做 RAG、要不要做本体"从二选一的技术题，转化为"这个业务需要哪种证据"的需求题。
- 与 [[concepts/来源溯源]] 直接相关：一一映射与最小证据包是把该分工落到数据层的具体工程手段。
- 与 [[concepts/本体与agent协同]] 相关：Agent 不产生事实，只负责把两类检索结果组织成上下文。

## 反例或边界

- 作者称本体与 RAG 都提供"事实依据"，但两类依据强度不同：本体给出的是建模后的确定事实，RAG 给出的是文档片段。两者冲突时以谁为准，本集未回答，见 [[queries/本体事实与rag依据冲突裁决待核验]]。
- 该分工成立依赖抽取质量、切分粒度与增量更新机制同时成立；原文改动、切分边界移动、对象合并后旧映射的维护未涉及。
