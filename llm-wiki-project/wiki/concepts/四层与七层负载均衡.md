# 四层与七层负载均衡

四层与七层负载均衡是按工作网络层次对负载均衡方案的划分：四层方案工作在传输层，不解析应用层内容；七层方案工作在应用层，可解析 HTTP 等协议内容。本页记录 [[架构师阿Q]] 第 5 集口播中对这一分工的描述，以及整理者补充的能力边界分析。

## 定义

视频作者在该段口播中给出的分工：

- **七层负载均衡**：Nginx 是七层负载均衡，支持 HTTP 协议；HAProxy 也是七层负载均衡软件。
- **四层负载均衡**：LVS 是纯四层的负载均衡，运行在内核态，作者称其性能是软件负载均衡中最高的，因为是在四层，所以也更通用一些。

## 来源观点（`unknown / 待外部核验`）

- 作者把「四层」与「性能高、更通用」绑定，把「七层」与「支持 HTTP 协议」绑定。
- 作者未展开四层方案的能力边界，仅以「更通用」一句带过。

## 已核验事实

本页暂无工具直接验证的事实。

## 项目分析（整理者补充，非视频作者原话）

- 四层的代价是不解析应用层内容，因此无法按 URL、Header、Cookie 做路由，也做不了七层的健康检查与内容改写。需要按域名分流、按路径灰度时，四层方案通常要配合七层组件一起用。
- 可延展方向：为负载均衡层建立一张职责表，把「连接分发」「协议解析」「灰度路由」「证书卸载」「限流」等能力逐项标到四层或七层，用来判断某一层是否被用超了范围。
- 与 [[控制面与数据面分离]] 视角呼应：只走请求的架构性能好但可观测性弱，双向都走的架构可控但容易成为瓶颈。

## 反例与边界

- 「四层更通用」与「四层能力更弱」并不矛盾：通用指不依赖具体应用协议，能力弱指无法做应用层判断。本集只讲了前者。
- 本集未讨论四层与七层两级负载均衡在真实入口链路中的职责划分。
