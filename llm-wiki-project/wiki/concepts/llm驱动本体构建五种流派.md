# LLM 驱动本体构建五种流派

## 定义

"LLM 驱动本体构建五种流派"是视频作者零点未来在该集口播中提出的分类框架，用来归纳过去两年学术界与工业界用 LLM 从文档构建 Ontology 的不同应对方式。五种流派分别是：拆解派、聚类派、两步走派、框架派、直给派。

需要强调：这是**作者的个人归纳，而非学术分类**，边界模糊，引用前宜先找到对应论文清单逐一比对。

## 来源观点（作者口播，`unknown`）

### 拆解派

核心思路是把一个很大的 Ontology 拆解成小的任务，每一步都用最合适的工具：提取实体、提取关系、去重归一、验证、存图，一步一步来。最关键的设计是**验证闭环**——每一个新的事实都要先通过结构化检查和逻辑检查，才能进入可信图谱；通不过的只能保留为日志，不让它污染知识库。

作者举例称法国电力公司 EDF 用这套方法管理核电站的技术文档。缺点是工程量非常大，前一步出错可能污染后一步；但若要上生产系统，作者称这是"目前最可靠的选择"。

### 聚类派

思路是"先别急着定义有什么东西，让数据自己去说话"：把文档中的名词提取出来，用密度聚类（如 AP 聚类）分组，再用 LLM 给每一组命名。作者解释为何不用 K-means——K-means 需要预先指定类别数量，而实际数据中并不知道有几类。

作者称代表性论文是 2025 年的 `LLM for Ontology`（论文名待确认），流程为：输入文档 → 提取名词 → BERT 向量化 → AP 聚类 → LLM 命名 → 构建 Ontology。论文核心是三步关系提取法，构建"实体—relation—实体"三元组。优点是数据驱动、幻觉风险较低；缺点是聚类质量直接影响结果，开放域（如 Wikipedia 数据）上粒度可能过细。适合探索全新领域。

### 两步走派

先让 LLM 从文档提取概念清单，再整理成有上下级关系的层次结构，最后序列化生成标准格式。中间产物可人工审查、调整。适合快速输出一版草稿验证想法。作者称代表性论文为 `Onto1kg`（论文名待确认）。

### 框架派

先有一个已存在的框架（如 Wikidata），定义好可以有什么类型、什么关系，再让 LLM 基于该框架提取实体，不能乱发明。可减少幻觉，输出天然符合共识与合规。适合已有行业标准规范的领域，如医疗、法律、电力。

### 直给派

端到端的 prompt 方式，设计一个 prompt 让 LLM 直接从文本输出 Ontology。实现最快（半小时可出结果），但幻觉风险最高、质量不稳定，prompt 一变结果可能完全不同。适合快速验证想法与学习理解 Ontology，不适合生产系统。

## 项目分析

- 五种流派并非互斥：直给派加约束即带拆解派成分，作者的 OntoPrompt 本身就是"直给派 + 约束规则"的混合体。
- 五种流派没有一种同时满足"快、准、可维护"，选型框架本质上是在让人承认这个取舍。
- 与现有 [[concepts/本体建模业务定义数据映射与关系校验]] 的建模路径描述可能重叠或口径不一，需比对。

## 反例与边界

- 拆解派：前一步错误会污染后一步；工程量最大。
- 聚类派：开放域粒度易过细，适合探索而非交付。
- 框架派：要求行业已有标准 schema，医疗、法律、电力之外的领域未必有现成框架。
- 直给派：prompt 极度敏感，只能停在 PoC。
