# 控制权边界

控制权边界是整理者在 [[架构师阿Q]] 第 5 集基础上提出的一个选型分析维度：判断一项能力究竟由平台承诺、协议保证，还是由他人缓存决定，再决定是否把它放进关键路径。**该框架由整理者提出，不是视频作者的原话。**

## 定义

问清楚一项能力是平台承诺的、协议保证的，还是别人缓存决定的，再决定是否把它放进关键路径。

## 来源观点（视频作者口播，`unknown / 待外部核验`）

本集并未使用「控制权边界」这一术语，但其对 DNS 负载均衡的批评为该框架提供了原始素材：

- DNS 记录的生效时间由运营商缓存决定，且缓存很有可能不遵循 TTL 规则，导致故障切换延迟大。
- DNS 的调度策略由协议能力决定，作者称其一般只支持轮询。

## 项目分析（整理者提出）

- 作者对 DNS 方案的两条批评都不是「功能不够」，而是「控制权不在你手里」。
- 对照后文，LVS 的卖点恰恰是把这两件事拿回来：立即切换、算法可选。
- 由此得到的通用教训：把控制权交给他人缓存的机制，不适合放在需要快速切换的关键路径上。
- 可追问：如果 DNS 的生效时间不可控，那么在类似 CDN 这种依赖 DNS 调度的系统里，故障切换的兜底应该放在哪一层？

## 反例与边界

- 该框架目前只有 DNS 一个来源案例支撑，尚未在其他来源中验证其解释力。
- 本框架属整理者分析，证据状态为 `unknown`，不应作为已确认结论使用。
