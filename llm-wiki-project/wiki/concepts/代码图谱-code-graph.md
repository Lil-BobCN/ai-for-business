# 代码图谱（Code Graph）

代码图谱（Code Graph）是视频作者在"零点未来：AI+企业"第 9 集中提出的一个概念，指把源代码、抽象语法树、依赖关系与执行关系组织成的一张可查询的代码内部管网图。作者称它是五张图里"最好懂的"一张。

## 定义（作者口径）

作者在该段口播中提出：代码图谱本质上就是一个**代码的内部管网**——画起来就是代码内部管网的网络图。

它包括一些函数、类、模块，这些就是节点；谁调用谁、数据怎么流、谁继承谁、文档在哪里等等。

作者给出的构成公式：**源代码 + 抽象语法树 + 依赖关系 + 执行关系**。要先解析成语法树，再推导出谁调用谁、数据往哪里流，整个软件系统就会变成一张可以查的图。

## 使用时机（作者口径）

作者说，当你一个软件代码量大到人脑记不住这个关系的时候，就可以去建立一张 code graph。改一行代码之前，先顺着图看一下谁会被受影响。

作者打比方：代码世界就像一张水电的管网图——管线怎么走、阀门在哪，关掉这边那边会停水；改代码之前，都去做一些风险预演。

## 项目分析

- 作者给的使用时机很具体：不是等人来查文档，而是在动手改一行代码之前。这等于把代码图谱的验收标准，从"图画得全不全"换成了"能不能在下刀前回答影响面"。
- 与 [[图谱工程-graph-engineering]] 的区别：代码图谱是"系统知道什么"侧的静态产物，图谱工程是"系统怎么干活"侧的执行编排。

## 反例与边界

- 代码图谱是静态产物，而代码每天都在变，图谱的新鲜度可能比覆盖度更决定它有没有用。
- 作者给出的边界：只在"代码量大到人脑记不住"时才值得建；探索性、一次性、不需要稳定结果的场景并不需要它。

## 开放问题

- 代码图谱与主干代码的同步延迟是否应作为运维指标？
