# 本体检索策略选型

本体检索策略选型是指在多种本体检索方式之间，根据问句特征选择合适检索路径的方法。视频作者木羽Cheney 在该集口播中给出了一条单维路由标准：按"问题明确度"在结构化查询、图遍历与向量召回加图扩展之间做选择。

## 定义

作者给出的选型规则如下（归属视频作者口播，`unknown / 待外部核验`）：

| 问句特征 | 选用策略 | 说明 |
|---|---|---|
| 条件比较明确 | 结构化查询 | 让 Agent 接入本体业务模型，生成结构化查询语句 |
| 需要追查多跳关联 | 图遍历 | 查找某个对象关联的多链、多跳信息 |
| 描述性比较模糊 | 向量召回 + 图扩展 | 用 embedding 搜索相似实体，再沿图遍历取全量信息 |

## 来源观点

作者称这三种策略"可以互相组合"，并强调它们共同服务于同一个目标：给 Agent 提供必要的运行时上下文。作者还称本节课程配套提供了三个 skills，一对一对应三条链路。

## 已核验事实

- 本页路由标准完全来自视频作者口播，无对照实验或评测数据支撑，属 `unknown / 待外部核验`。
- 三种策略各自的原理描述见 [[结构化查询]]、[[图遍历与bfs扩展]]、[[向量检索与图扩展]]。

## 项目分析

- 这条标准把"怎么问"作为唯一分岔口，结构清晰、便于向业务方解释，可直接用作任何"结构化数据 + 图 + 向量"混合检索系统的设计起点。
- 但实际系统还会受另外几个变量约束：本体覆盖度、图数据实时性、查询延迟与成本预算。它们同样决定哪条路才走得通。
- 作者未讨论三种策略给出冲突答案时以哪条为准，也未讨论组合时的降级路径。

## 反例或边界

- **单维标准的局限**：仅以"问题明确度"分岔，忽略了数据完备度、实时性与成本。
- **失败路径缺失**：结构化查询翻译失败后是否回退向量召回，向量召回错误时图扩展是否放大错误，均未讨论。
- **冲突仲裁缺失**：三种策略结果冲突时无优先级规则。
