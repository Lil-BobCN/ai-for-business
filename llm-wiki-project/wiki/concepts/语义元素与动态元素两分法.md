# 语义元素与动态元素两分法

## 定义

语义元素与动态元素两分法是视频作者零点未来在「AI+企业」第 5 集中引述的一种 Ontology 能力划分：Palantir 官方把 Ontology 的能力分为 Semantic elements（描述世界）与 Kinetic elements（改变世界）两类。前者回答「企业里有什么、谁跟谁关联」，后者回答「能改什么、能算什么」。

## 来源观点

以下均为视频作者在该段口播中提出的观点，属 `unknown / 待外部核验`。

- **Semantic elements（描述世界）**：
  - Object Type，如 Order、Warehouse、Customer；
  - 属性，如 Status、ETA、Priority；
  - Links，如 Shipment 归属于 Order、Order 归属于 Customer。
- **Kinetic elements（改变世界）**：
  - Actions，如 Update Shipment ETA，以函数形式存在，动态更新运输预估到达时间；
  - Functions，如计算延迟风险、优化调度。

作者据此强调：Palantir Ontology 的核心不是把一张表换个名字叫本体，而是把企业的名词、关系、规则、动作、权限都放进一个受治理的语义层。作者认为 Kinetic elements 解决的是 Agent 如何从「回答问题的工具」变成「真正帮助执行业务、产生业务价值的工具」。

## 项目分析

- 该两分法是理解「Ontology 是操作层而非知识图谱」这一主张的关键切分：只有承认动词（Actions、Functions）也需要被建模、被授权，Ontology 才不只是描述性结构。
- 与 [[concepts/本体作为约束层]] 呼应：能被执行的动词和能被描述的名词一样，都需要事先被定义、被授权；没被建模成 Action 的业务动作，Agent 不会凭空发明出来。
- 与 [[concepts/ontology与数据库schema的三点差异]] 存在潜在张力：该页强调 Ontology 与 schema 的差异，本集进一步主张 Ontology 是「操作层」，需确认两者是否一致。

## 反例或边界

- 作者未说明一个业务动作若未被预先建模，Agent 应报错停下还是退回给人接手。
- 两分法的官方命名与划分依据未给出一手出处，需外部核验。
