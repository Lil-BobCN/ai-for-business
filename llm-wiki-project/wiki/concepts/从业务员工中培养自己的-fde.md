# 从业务员工中培养自己的 FDE

「从业务员工中培养自己的 FDE」是「零点未来：AI+企业」第 10 集提出的核心组织方法：企业不把造 Agent 的活外包给工程师和外部 FDE，也不集中交付，而是在业务团队内挑选并培养具备跨技术能力的人来造 Agent，让「造 Agent」的能力长在业务内部。

> 归属说明：本页为该视频作者的主张，属 `unknown / 待外部核验`。

## 定义

作者描述的路径是：在业务团队里找一批「非常懂业务、又有一些跨技术能力」的人（本集称 Echo〔ASR 待确认〕），他们知道流程里哪一步跑得最慢、哪些例外最麻烦，也能把经验和反馈带给中央 AI 团队；AI 团队提供工具、模板和护栏。

## 来源观点

- 作者认为，企业 AI 落地最常见的断层是「懂业务的人不会做 AI，懂 AI 的人又不可能吃透公司每一条流程」，FDE 正是为填补这一断层而生。
- 但当企业有非常多场景（例如 100 个）要上 Agent 时，FDE 自己会成为新瓶颈；外购 FDE 只是把排队换成预算。
- 解法是把「造 Agent」的能力下放到业务团队，从业务员工中培养自己的 FDE。
- 作者称 ABC Legal 的实践是：CTO 找来十五人委员会（财务、市场、运营、销售，无软件开发者），一周内全员做出可运行 Agent，一个月内公司约 50 多个 Agent 上线。

## 已核验事实

无。本集未提供独立一手资料。

## 项目分析

- 这条路径与既有 [[concepts/fde交付方法]] 的关系是「口径演进」而非替代：FDE 从「交付 Agent」转向「帮企业建立持续生产 Agent 的能力」。
- 与 [[entities/echo与delta双团队模型]] 相关：本集给出 Echo 的另一种用法（业务内生的 Agent 生产者），需与既有 Echo/Delta 口径比对。
- 隐含前提：业务人员的「跨技术能力」确实可培养——作者用一周全员出成果支持，但样本是 15 个被挑出来的委员会成员。

## 反例或边界

- 作者自陈：非技术人员能造 Agent ≠ 谁都能轻易上线；治理是前置条件。
- 若业务场景高度耦合、需跨系统改造，业务人员自建未必可行。
