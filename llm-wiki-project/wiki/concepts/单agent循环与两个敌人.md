# 单 Agent 循环与两个敌人

本页记录「零点未来」第 8 集视频作者对单个 Agent 设计模式的拆解。作者把它定位为自主性阶梯的中段。

## 定义（来源观点，`unknown / 待外部核验`）

视频作者在该段口播中提出，单个 Agent 的模式本质非常简单，就是一个 while loop（循环）：把 LLM 输出的内容反馈回去，让 LLM 基于真实环境的反馈和结果来校准自己，而不是凭空猜。

## 三个退出条件

1. 调用了最终的输出工具；
2. 模型直接返回答案；
3. 达到了最大的迭代次数。

## 两个敌人与对策

### 敌人一：重复无效的调用

模型反复调用同一个工具，拿到同样一个「死」的结果，这种情况下就没有效果了。

- 对策：设一个迭代上限和超时的限制；
- 工具报错时，先反思是不是参数错了，还是问用户有没有问题。

### 敌人二：工具非常多

作者称，如果工具超过 10 个，而且这些工具可能还非常相似，那模型就会开始选错工具。

- 对策：用清晰的命名去描述它、说明什么情况下可以用什么工具，给它一个范围。

## 项目分析

- 作者把工具数量的天花板归因于接口设计问题，而非单纯的模型能力问题：瓶颈在于「什么时候该用哪个工具」没有被写清楚。
- 可延展方向：把工具的命名和调用条件当作提示词的一部分来验收，而不是留给调用者临场判断。

## 反例或边界

- 「工具超过 10 个且彼此相似就选错」这一量级与模型版本、工具描述质量强相关，换模型或重写描述即可能失效，不宜当硬指标。
- 迭代上限与超时是工程兜底，但作者未讨论上限设置过低导致任务被截断、过高导致成本失控的取舍。
