# 上下文图谱（Context Graph）

上下文图谱（Context Graph）是视频作者在"零点未来：AI+企业"第 9 集中提出的一个概念，指在知识图谱基础上补充任务状态、事件与历史决策，形成面向 Agent 的、用来做决策的业务上下文地图。作者称它是"今天最容易讲错的一张图"，因为厂商、学术界与他自己的用法并不一致。

## 定义（作者口径）

作者在该段口播中提出：知识图谱描述的是实体关系和事实，而上下文图谱是在它的基础上加了一些**任务状态、事件和一些历史的决策**，形成了面向 Agent 的、用来做决策的业务上下文地图。

它告诉你的是：某张表现在质量怎么样、谁负责改了哪一列、谁会被影响、谁批准过什么样的一个例外；它跟业务做实时更新，然后 Agent 就有一个正常的上下文，能够去干实际的活。

作者用一句话把前两张图串起来：knowledge graph 告诉 Agent 企业有什么，context graph 告诉 Agent 当前为什么重要、以及如何基于这些信息来帮助我们做决策。

## 三层结构（作者或厂商整理，非通行定义）

- 底层：**语义基础**——实体是什么意思
- 中间：**元数据**——数据血缘、数据来源、质量分、负责人、可见范围
- 顶层：**决策轨迹**——谁在核实、为何批准了什么

## 三方定义分歧（本来源最有价值的可迁移素材）

作者在该段口播中没有把差异抹平，而是把三种用法并排放着：

1. **厂商口径**：一些数据平台厂商，如 DataHub 与 `Atlant`（疑为 Atlan，ASR 拼写待确认），站在一家公司的角度，更注重决策轨迹和治理。
2. **学术论文口径**：作者称有一篇论文把 context graph 定义为在知识图谱基础上，为反映当前状态与上下文信息，增加时间、地点、出处、置信度等信息。作者举例：A 先生住在上海与 A 先生住在北京，在知识图谱里是两个冲突事实；若加上时间关系（上个月住上海、这个月住北京），它就成立。作者未给出论文出处。
3. **作者口径**：企业此刻的业务上下文。

## 使用场景（作者口径）

- AI Agent 进公司干活之前，需要一个可信的业务上下文地图，理解事情本身、关联数据与 KG 信息。
- 影响分析：改了某张表，哪些仪表盘可能会坏掉。
- 审计与归因：追溯谁在核实、因为什么批准了什么东西。

## 项目分析

- 本来源**扩展**了既有知识：引入 context graph 这一此前 Wiki 未覆盖的概念，并**挑战**了"本体/知识图谱"二分的既有口径（新增"当下状态"这一层）。
- 与 [[本体给事实-rag给依据]]、[[本体作为约束层]] 的边界可交叉引用：context graph 与 RAG 都涉及"给事实补依据"，但前者强调任务状态与决策轨迹，后者强调文档证据。
- 与 [[agent与ontology五层交互架构]] 可衔接：context graph 可视为 Agent 与 Ontology 交互中的"当下状态"层。

## 反例与边界

- 作者自己承认 context graph 一词在数据平台厂商、学术界和他自己的用法之间并不一致。
- 在真实系统里，Agent 每次执行都会产生新的状态和决策记录，这些记录本身又会回流成上下文图谱的输入，"知道什么"与"怎么干活"的边界是流动的。
