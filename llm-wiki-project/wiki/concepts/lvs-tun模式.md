# LVS TUN 模式

LVS TUN 模式是 LVS 三种工作模式之一，全称 IP Tunneling（IP 隧道技术）。其核心特征是在客户端请求报文外再封装一层 IP 报文，从而支持跨机房部署。本页记录 [[架构师阿Q]] 第 5 集口播中的报文流转描述。

## 定义

视频作者在该段口播中说明：TUN 全称 IP Tunneling，即 IP 隧道技术，通过在原有报文外再封装一层 IP 报文完成转发。

## 报文流转（视频作者口播，`unknown / 待外部核验`）

1. 客户端将请求发往前端的负载均衡器：请求报文源地址是 CIP，目标地址为 VIP。
2. 负载均衡器收到报文后，发现请求的目标地址在规则里面存在，于是在客户端请求报文的头部再封装一层 IP 报文，将源地址改为 DIP、目标地址改为 RIP，并将此包发送给 Real Server。
3. Real Server 收到请求报文后，首先拆开第一层封装，发现里面还有一层 IP 头部、目标地址是自己 lo 接口上的 VIP，所以会处理此请求报文，并将响应报文通过 lo 接口送给 ETH0 网卡**直接发送给客户端**。
4. 作者提示：ETH0 网卡一般是和 Director Server 在一个网段的网卡，注意需要设置 lo 接口的 VIP 不能在公网上出现。

## 特点（视频作者口播）

- 支持跨机房部署。
- 隧道封装、解封装带来额外开销。
- Real Server 需支持隧道协议且需配置 VIP。

## 已核验事实

本页暂无工具直接验证的事实。报文流转描述来自本地 ASR 转写，证据状态 `partial`。

## 项目分析

- 用「三问」记法定位 TUN 模式：在报文外**加一层 IP 封装**；响应报文**不走过**调度器；拓扑约束是后端需支持隧道协议并配置 VIP。
- 与 DR 模式相比，TUN 用封装开销换取了跨机房能力，即不再要求调度器与 Real Server 处于同一广播域。
