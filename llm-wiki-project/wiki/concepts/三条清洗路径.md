# 三条清洗路径

"三条清洗路径"是本来源视频作者对清洗解析阶段的划分：结构化、半结构化、非结构化三类数据各自走一条固定动作的路径，最终都产出标准表。本页内容属作者口播观点，`unknown / 待外部核验`。

## 定义

- **结构化路径（CSV/Database）**：最简单。用 Apply Schema 按钮扫描 CSV 样本自动识别时间/数字/文字类型，再用拖拽式 Pipeline Builder 过滤去重，得到 Clean Flight 表。
- **半结构化路径（JSON/XML）**：核心操作 Explode，把嵌套结构炸开摊平。一份预订 JSON 变成乘客表与预订表，用订单 ID 关联。
- **非结构化路径（PDF 扫描件）**：必须让 AI 读。由 AIP Document Intelligence 承担五步流程（存 MediaSet → OCR+多模态输出 Markdown → 解析业务字段 → 校验复核 → 输出 Clean Maintenance 表）。

## 来源观点

作者认为三条路径的固定动作可以复用：自动推断 Schema、Explode 摊平嵌套、OCR 加多模态转 Markdown 后抽字段。三条路里只有第三条是"让 AI 读"，而人工抽样被放在它后面，等于承认准确率不能靠模型自证。

本页暂无经工具直接验证的事实。

## 项目分析

三条路径的划分与 [[rag三种实现路径]] 相关但不同：后者关注检索侧的实现方式，前者关注数据进入本体前的清洗方式。两者可组合——清洗路径决定数据形态，检索路径决定数据如何被消费。

## 反例与边界

- 非结构化路径的准确性依赖人工抽样，但样本量与判定标准作者未给出。
- 半结构化路径的 Explode 在深层嵌套或数组套数组时可能产生行数爆炸，作者未讨论。
