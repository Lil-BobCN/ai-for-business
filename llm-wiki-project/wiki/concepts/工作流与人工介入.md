# 工作流与人工介入

工作流与人工介入，是把任务步骤、分支、状态转换和需要人判断的节点显式组织起来，使 Agent 在明确边界内执行，并在指定条件下交由人工处理的方法。

## 任务组织建议

视频作者给出三类任务组织建议：

| 任务条件 | 作者建议 |
|---|---|
| 固定流程和分支 | 通过 workflow 或 skills 编排 |
| Agent 根据意图自主选择本体操作 | 使用 tool calling 或 MCP |
| 复杂任务或需要人工介入 | 使用 sub agents，或 workflow 加 Agent |

作者强调，如果流程包含人机交互，应在 workflow 中明确人工介入的场景，不应把人工步骤留在隐含状态中。workflow、skills、sub agents 和 tool calling 可以组合；固定流程不必强行交给自主 Agent，复杂任务也不应只依赖自然语言提示来隐含表达人工边界。

视频没有提供这些组织方式之间的测量、失败率或维护成本比较。

### 第 1 集的人工审核预告

### 第 4 集的风险控制观点

第 4 集作者以退款、删除信息等操作为例，提出高风险动作不应由 AI 不受限制地自行执行；遇到业务流程异常时，可以暂停并交由人工确认。这是作者提出的控制原则。来源没有给出风险分级、审核权限、触发条件或运行记录，不能据此认定实际系统已实现这些机制。

### 订单客服演示中的人工操作

订单客服演示中，客服点击启动 Agent 处理，并在生成回复后由客服发送。这说明演示界面保留了人工操作，但没有证明已经实现持久化审批、异常升级、权限控制、超时转人工或人工决策记录。

## 项目分析：可审计的人工节点

可审计的人机协同工作流至少需要记录：

- 进入人工节点的触发条件；
- Agent 已完成的步骤和工具调用；
- 待人工确认的事实或决策；
- 人工操作人、时间和处理结果；
- 返回 Agent 或结束任务的条件；
- 拒绝、超时和异常升级路径。

具体风险分级应由项目方结合业务和责任边界确定。以上属于工程设计要求，不是相关视频展示的完整实现。
