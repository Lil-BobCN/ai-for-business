# LLM 建本体的四道坎

## 定义

"四道坎"是视频作者零点未来在该集口播中提出的问题框架，用来描述用 LLM 构建 Ontology 时面临的四类核心困难。作者认为，过去两年学术界与工业界的应对方式可以归纳为五种流派。

## 来源观点（作者口播，`unknown`）

1. **类型数量未知**：在构建一个领域的知识地图之前，不知道里面有多少种类型——是十种还是一千种；即便对人来说，也不一定了解有多少个实体类型。
2. **LLM 幻觉**：LLM 可能创造出输入数据里根本没有的概念，并把这些想象当成事实。
3. **粒度难控**：关系太宽泛没有用，太细又没人能维护，有些实体之间联系又太密；什么粒度更合适本身是难题。
4. **评估无标准答案**：建什么样的 Ontology 没有标准答案，也没有对错之分；如何评估好坏、建完能不能用，也是问题。

## 项目分析

- 前两道坎是工程问题——类型枚举可靠数据探索补齐，幻觉可靠校验压制；后两道坎不是。粒度合适不合适、本体好不好，取决于业务上要拿它回答什么问题，而这恰恰没有客观答案。
- 第四道坎与现有 [[queries/本体建模两条路径的验收标准待核验]] 直接呼应。
- 若第四道坎没有标准答案，那么"双重验证通过"到底验证的是正确性，还是仅仅验证了自洽性？见 [[queries/本体验证规则来源与自证风险待核验]]。

## 反例与边界

作者自己给出的边界：直给派半小时出结果但 prompt 一变结果全变；聚类派在开放域上输出过细粒度；框架派要求行业已有标准 schema；拆解派工程量最大且前一步错误会污染后一步。
