# 本体建模：业务定义、数据映射与关系校验

本体建模：业务定义、数据映射与关系校验，是一种先明确领域业务含义，再把多来源数据整理并映射到对象、属性、关系和约束，最后通过业务校验与测试确认关系是否可用的建模方法。本页根据单一视频来源整理，方法框架属于视频作者的方向性主张，尚未被独立项目证据验证。

## 定义

该方法把本体建设拆为两个相互依赖的工作面：

- **业务定义**：决定领域边界、对象或类型、属性、关系、`link type` 和约束。
- **数据映射**：处理 API、数据库、CSV、PDF 等来源，完成格式统一、清洗、实体识别、关系识别和映射。

二者最终共同形成可供查询或推理的业务关系网。来源把该关系网与知识图谱进行类比，但没有给出形式化本体语言、标准 Schema 或实现代码，因此不能据此认定它等同于某种具体本体技术。

## 来源观点

视频作者在口播中将 Ontology 描述为领域概念、属性、关系和约束的模型。在电商客服示例中，订单、顾客、商品等可以作为业务对象；对象的属性和对象之间的关系则构成业务定义的基本结构。

作者还把本体建模中的关键问题概括为：

1. 业务关系网应当如何定义；
2. 分散的原始数据如何整理成符合业务含义的数据形式；
3. 建成后如何验证关系和业务效果；
4. 库存、订单等业务数据变化后如何持续更新。

以上内容均属于视频作者观点，来源证据为本地 ASR，状态为 `partial`。

## 建模步骤

### 1. 划定领域边界

先确定本体要解释的业务范围，以及不同业务、技术或风控语境是否使用同一套定义。来源只说明本体服务于具体领域，没有给出跨域合并、分域维护或术语冲突的裁定规则。

### 2. 抽象对象与类型

把业务中需要被识别、查询或关联的对象抽象出来，例如订单、顾客、商品、包裹或物流记录。对象是否应当建模为实体、事件、状态还是关系中间对象，需要结合业务生命周期和查询目标确认，不能仅凭自然语言中的名词分类决定。

### 3. 定义属性

为每类对象确定核心属性和状态，例如订单标识、顾客标识、商品信息、包裹状态或物流时间。属性名称、数据类型、是否必填、取值范围和来源系统需要通过实际数据和业务方确认；本集没有提供字段级定义。

### 4. 定义关系与约束

明确对象之间的关系及其方向、基数、条件和业务约束。例如顾客与订单、订单与商品、订单与包裹、包裹与物流记录之间的关联，都需要说明身份依据和有效条件。

来源使用了 `properties`、关系和 `link type` 等词，但没有给出关系 Schema、主键规则、约束语言或验证器配置。

### 5. 处理并映射原始数据

把 API、数据库、CSV、PDF 等来源统一到可处理的格式，清洗脏乱数据，并识别人名、地名、订单和它们的关系，再将结果映射到业务对象、属性和关系中。

当前分析认为，清洗时已经包含业务语义判断，因此“先清洗后建模”与“先建模后清洗”不能简单视为严格的线性顺序。清洗规则和本体定义可能需要共同演化，具体边界仍待核验。

### 6. 关系校验与业务测试

在关系进入 Agent 上下文或工作流前，至少要确认对象身份、关系方向、状态和时间口径是否符合业务含义，并使用真实业务问题测试关系网是否支持目标任务。

“需要大量测试”是视频作者的方向性说法。本集没有给出测试集、指标、基线、通过阈值或责任归属。

### 7. 持续更新

订单、库存和物流等实例数据会变化。当前分析建议将实例数据刷新、关系有效性变化和本体定义或版本变化分别记录，避免把所有更新都称为“本体更新”。详细边界见 [[本体校验与持续演化]] 和 [[本体与数据约束及版本演化待核验]]。

## 电商客服示例的建模提问

来源中的电商场景可转化为以下提问顺序：

```text
当前对象是什么？
  -> 顾客、订单、商品、包裹还是物流记录？

对象有哪些属性？
  -> 标识、状态、时间、数量、来源和业务标签是什么？

对象之间有什么关系？
  -> 顾客下单、订单包含商品、订单关联包裹、包裹对应物流记录如何表示？

关系的约束是什么？
  -> 一个订单是否可以有多个包裹？商品与包裹是否一一对应？状态冲突如何处理？

数据来自哪里？
  -> API、数据库、CSV、PDF 或其他业务系统？

如何确认关系正确？
  -> 客户确认、规则校验、回归问题和业务结果分别承担什么职责？
```

这组问题是当前分析从来源框架中整理出的工作清单，不是视频作者提供的正式模板。

## 反例与边界

- 数据清洗过程中识别实体和关系，已经涉及业务语义判断，不能把清洗视为完全中性的预处理。
- 订单系统、物流系统和知识库可能对同一对象给出不同状态，来源没有说明权威来源、时间窗口或冲突处理规则。
- 订单和库存实例的变化不一定意味着本体模式或业务定义变化。
- 关系网能支持查询不等于具备 OWL 推理、规则引擎、权限控制、事务更新或生产级审计能力。
- 错误关系可能污染 Agent 上下文，但本集没有提供错误检测、回滚和人工复核机制。
