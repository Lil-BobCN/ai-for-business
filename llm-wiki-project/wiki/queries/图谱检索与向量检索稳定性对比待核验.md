# 图谱检索与向量检索稳定性对比待核验

## 问题本身

视频作者 catface996 主张"图谱关系检索比向量检索稳定"，但演示中承认目前仍以关键字检索为主、语义检索尚未启用。主张与实现存在落差，需核验。

## 当前已知（作者口播，`unknown`）

- 作者主张：传统 RAG 靠语义匹配不稳定；通过图谱关系去查"非常稳定"，同一任务换不同 agent 应查到同一份规范。
- 作者承认：目前做 instance 检索基本使用关键字，还没用特别好的语义检索；技术上已支持，后续会调语义检索。
- 作者设想的语义检索路径：根据输入语义生成可能的 Spec instance，再向量化，到向量库（原文作"相量飞铺"，待确认）检索。

## 冲突来源

- 作者主张（图谱检索稳定优于向量检索）vs 演示现状（仍以关键字检索为主）。

## 缺口

- 缺少"检索稳定性"的可测量指标与对比实验。

## 建议搜索式

- 图谱检索 向量检索 稳定性 对比 企业知识
- GraphRAG 检索一致性 评测
- 本体 图谱 关系检索 命中一致性

## 下一步研究动作

- 把"检索稳定性"当作可测量工程指标，比较向量检索与图谱检索在同一批任务上的命中一致性。
- 讨论哪些类型的知识适合放进哪一种检索通道。
