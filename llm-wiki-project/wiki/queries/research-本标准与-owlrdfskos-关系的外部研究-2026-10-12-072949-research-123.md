# GB/T 48000.3-2026 与 OWL/RDF、SKOS 关系的外部研究

> **主题界定**：依据所收集的 5 条来源，本页所称“本标准”指 [[gb-t-48000-3-2026-本体建模要求|GB/T 48000.3-2026《标准数字化 第3部分：本体建模要求》]]。若主题中的“本标准”另有指代，需重新界定证据范围。

**结论速览**

- 外部来源一致指向 W3C 语义技术栈（RDF/RDFS、OWL、Turtle、JSON-LD、SHACL），与 wiki 既有概念页 [[owl-rdf语义建模]] 的记录方向一致 [4][5]；
- **SKOS 在全部 5 条外部来源中零出现**，标准与 SKOS 的关系目前没有外部证据（无论支持还是否定），属明确缺口；
- “14 类实体 + 34 对象属性”“规定 OWL+Turtle+SHACL”等具体断言来自行业二手文章，且无条款号引用，需与正式发布文本比对（wiki 已有待核验页 [[gb-t-48000-3-2026-正式版与征求意见稿差异待核验]]）。

## 3. 外部来源对 OWL/RDF 关系的表述

### 3.1 行业文章：OWL + Turtle + SHACL 技术栈 [4]

[4] 称 GB/T 48000.3-2026“规定 OWL+Turtle+SHACL 技术栈”，并将“14 类实体 + 34 对象属性”称为核心骨架；作者逐条对照自研 ERP 本体后称“主干对齐”（该句在来源中即被截断）。其中“对象属性（object property）”本身即 OWL 术语，暗示标准的属性体系沿用了 OWL 的对象属性/数据属性二分，可与 wiki 的 [[数据属性与关系属性]] 对照核验。

### 3.2 行业资讯：W3C 语言、序列化与约束验证 [5]

[5] 称标准的“形式化要求不是炫技，而是为了互操作”：采用 XML、RDF/RDFS、OWL 等 W3C 推荐语言，用 Turtle、JSON-LD 存储和交换，支持基于 SHACL 的约束验证（来源在此处截断）。

### 3.3 商业翻译条目：OWL/RDF 术语定义 [3]

[3] 页面列出 “OWL: Web Ontology Language” 与 “RDF: Resource Description Framework” 定义，间接佐证标准（或其英译术语表）包含 OWL/RDF 术语。该来源为商业站点，可靠性有限，但可作为“术语是否出现”的旁证。

### 3.4 综合评估

- **相互印证**：两条独立二手来源 [4][5] 对技术栈的叙述高度一致——RDF/OWL 为建模核心、Turtle（及 JSON-LD）为序列化、SHACL 为约束验证；两者均提及 Turtle 与 SHACL。
- **细节漂移**：XML、RDFS、JSON-LD 仅见 [5]，[4] 未提及；说明二手转述存在清单差异，不能当作精确条款清单使用。
- **与内部证据一致**：wiki 既有页面 [[owl-rdf语义建模]] 以 OWL/RDF 语义建模为线索记录相关内容；外部来源可补充 Turtle、JSON-LD、SHACL 等具体技术名称，但均属待核验的外部主张。
- **技术层次混列**：来源将数据模型（RDF/RDFS/OWL）、序列化格式（Turtle/JSON-LD）与约束语言（SHACL）并列为“语言/技术栈”，属通俗归纳；标准条款中各自角色（如 SHACL 与 OWL 公理的分工，参见 [[本体公理]]）需另行区分。

## 4. SKOS：明确的证据缺口

- [1]–[5] 均未提及 SKOS，也未出现 skos:Concept、概念方案（concept scheme）、叙词表（thesaurus）、词表等关联关键词。
- 因此，现有外部研究**无法回答**：标准是否引用 SKOS、是否允许以 SKOS 表示标准中的概念体系与术语层级、或是否以 OWL 自定义类体系替代 SKOS。任何相关断言在获得条款级证据前都不应写入 wiki 正文。
- 可能的关联面（待核验的方向）：SKOS 的典型用途是概念体系/词表表示，与 [[smart标准概念模型]] 中的概念分层、[[标准本体]] 的概念层设计可能发生交叉；与 [[ontology-是操作层还是知识图谱]] 所讨论的概念定位问题也有间接关联。
- 核验路径建议：在正式发布文本中检索“SKOS”“skos”“概念方案”“叙词表”“词表”；核对“规范性引用文件”表是否列出 SKOS Reference；在 [3] 的英译全文术语表中检索 SKOS 是否作为术语条目出现；并检查相邻标准 [[gb-t-46917-3-2026-语义集成技术要求]] 的语义集成要求是否引用 SKOS。

## 5. 矛盾与待核验点

1. **二手来源与正式文本的落差**：[4][5] 可能基于征求意见稿或三手转述，且 wiki 已有 [[gb-t-48000-3-2026-正式版与征求意见稿差异待核验]]，技术栈断言在条款比对前只能视为“待核验的外部主张”。
2. **规范强度未定**：“规定 OWL+Turtle+SHACL”[4] 属通俗表述，标准条款可能使用“宜/可”等推荐性措辞；各技术的出现章节与约束级别均无出处。
3. **计数断言为单源**：“14 类实体 + 34 对象属性”仅见 [4] 一处，需与标准正文的实体类型表、属性表逐项比对。
4. **命名空间缺环**：RDF/OWL 语境下 IRI 命名空间是基础构件，但外部来源均未涉及；wiki 记录的 [[标准本体iri命名空间占位符待核验]] 与之形成缺口，需在正式文本中确认占位符处理方式。
5. **语义细节缺口**：外部来源未说明标准的实体类型是否映射为 owl:Class、关系类型如何映射为 owl:ObjectProperty、约束如何对应 SHACL 形状，也未涉及 [[约束类型属性跨类语义漂移待核验]]、[[关系名称重复歧义待核验]] 等语用问题。
6. **来源时效**：标准 2026-01-28 发布 [3]，行业文章未标注发布时间，引用时需回查其写作时点。
