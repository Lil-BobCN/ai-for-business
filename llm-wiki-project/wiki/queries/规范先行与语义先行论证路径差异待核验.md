# 规范先行与语义先行论证路径差异待核验

## 问题本身

“标准数字化”标准族体现的“规范先行、实现后置”方法论，与资料中“语义先行，AI 才能跑起来”的主张，方向一致但论证路径不同。两者是否真的相互支持，需要单独讨论与核验。

## 当前已知

- 本文档第六节提出（**当前分析，非标准原文**）：标准族的推进顺序是“先定参考架构 → 再定本体建模 → 再定语义单元 → 再定接口 → 最后定平台”，即规范先行、实现后置。
- 该顺序与 Wiki 中“语义先行，AI 才能跑起来”的主张方向一致。
- 但两者论证路径不同：一个是标准体系的制度安排，一个是产品实践的经验总结。

## 冲突来源

- 标准体系路径：以规范性文件、参考架构、本体建模要求等制度性安排为论证依据。
- 产品实践路径：以商业产品落地经验总结为论证依据。
- 两者是否相互支持，本文档未给出证据，仅建议单独开 query 页讨论。
