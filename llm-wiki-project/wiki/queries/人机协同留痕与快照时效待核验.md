# 人机协同留痕与快照时效待核验

## 问题本身

当 Agent 因事实冲突等原因暂停、由人工介入判断后，人工判断本身出错时的裁决、留痕与回滚机制是什么？以及 LangGraph checkpoint 保存的快照在人工长时间未处理时是否仍然有效？

## 当前已知

- 视频作者在该集口播中演示：人工仅提交一条补充意见（“可以和物业前台确认一下”）即交回 Agent，Agent 恢复执行并生成草稿。
- 作者用“把某一份快照停在这里”解释 checkpoint，隐含了状态可完整序列化、可长期保存、可在恢复时仍然有效。
- 作者未涉及人工判断与系统事实冲突时以谁为准、在哪里留痕。

## 冲突来源

- 本集称“把业务规则写进本体 schema 即可触发中断”，而既有 [[本体与数据约束及版本演化待核验]] 正关注约束的生效时机与版本演化——本集未解决这些开放问题，反而强化了其待核验性。
- 演示中人工没有推翻系统结论，而是在结论上追加了一条可执行的下一步；若人工坚持“再发一个”与系统事实冲突，系统以谁为准，口播未涉及。

## 缺口

- 人工判断出错时的复核与回滚机制缺失。
- 快照的时效性未约定：人工隔数日才处理时，检索事实是否仍成立、快照是否应过期重跑。
- 人工节点的审计字段（谁、何时、依据什么做了什么判断）未定义。
