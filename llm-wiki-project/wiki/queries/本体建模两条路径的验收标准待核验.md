# 本体建模两条路径的验收标准待核验

## 问题本身

视频作者在该集口播中提出本体建模的两条路径：有既有模型则基于它构建、反复调试；没有既有模型则梳理需求痛点交 AI 出方案、人工逐轮判断。但本集未回答：这两条路径的产物应如何验收？本体的完整度应按"覆盖多少业务问题"来验收，还是按"Schema 是否严谨"来验收？

## 当前已知

- 作者称有既有模型时，可"基于它来去进行初版的构建，然后反复地去进行调试"，把本体接入 Agent 在不同业务场景下测试，出问题就即时调整约束规范。
- 作者称没有既有模型时，"把需求梳理出来，把痛点需求梳理出来，把技术架构方案梳理出来"，让 AI 出方案、出判断、出结论，由人工逐轮判断、修订、确认。
- 作者强调"不要自己定义，交给 AI"，但判断权仍在人手里。
- 作者在收尾时把本体定位为"给 Agent 提供上下文的关系网"。

以上均为作者口播观点，`unknown / 待外部核验`。

## 冲突来源

- 本集未提供失败案例与验收标准的对照说明。
- "更快的实现思路""最快捷的技术方案"这类表述只是预告，本集并未给出可比的数据。
- 与 [[文件格式与业务模型分离]] 相关的开放问题（同一业务在 PDF 与 CSV 两种来源下抽出的本体如何验收一致性）也缺少答案。

## 缺口

1. 两条路径各自的验收标准、验收人、签字责任未定义。
2. "AI 出方案"路径缺少失败案例与停止信号。
3. 本体完整度的度量口径（业务问题覆盖 vs Schema 严谨）未确定。

- enterprise ontology validation acceptance criteria LLM generated
- FDE ontology delivery acceptance checklist
