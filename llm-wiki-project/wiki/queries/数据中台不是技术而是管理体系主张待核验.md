# 数据中台"不是技术而是管理体系"主张待核验

## 问题本身

视频作者在《第 3 集｜一口气讲透大数据、数据库、数据仓库、数据湖、数据中台的底层原理》中提出："数据中台不是技术，而是一套管理体系。"该判断是否有独立一手资料支持，还是仅为作者主张？

## 当前已知

- 作者给出的核心机制是数据资产化与服务化：把常用数据加工成标准化资产，封装成 API 接口。
- 作者给出的动因是企业级管理问题：各部门数据不通、统一指标结果差一大截、分析重复写 SQL、多业务线重复开发用户标签。
- 作者只讲了收益侧，未讨论中台与业务线的权责划分、投入产出争议及"中台做不动"时的退出机制。

## 冲突来源

本集未呈现反方观点。行业对数据中台存在争议：中台建设在实践中既有成功案例，也出现过投入巨大而收益不清的争议与后来的组织调整。本 Wiki 现有页面 [[concepts/业务中台与数据中台]] 记录了相关口径，需核验与本集判断是否一致。

## 缺口

- 数据中台"管理体系"属性的独立一手资料（厂商白皮书、学术研究、企业复盘）。
- 中台建设失败或调整的公开案例与原因分析。
- 中台与业务线权责划分的实践模式。

## 建议搜索式

- 数据中台 管理体系 定义 争议
- 数据中台 建设失败 复盘 组织调整
- 数据中台 与 业务中台 权责划分 实践

## 下一步研究动作

检索独立一手资料，核验"数据中台不是技术而是管理体系"这一判断的出处与支持度；同时核对 [[concepts/业务中台与数据中台]] 的既有口径，必要时创建或更新相关 query 页面记录冲突。
