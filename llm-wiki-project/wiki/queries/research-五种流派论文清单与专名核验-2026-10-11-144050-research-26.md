# Research: 五种流派论文清单与专名核验

# 五种流派论文清单与专名核验

## 核验目标与方法

本页针对「LLM 驱动本体构建五种流派」的**论文清单与专名拼写**做外部证据核验。既有页面 [[llm驱动本体构建五种流派]] 给出了五种流派的框架，[[五种流派论文与案例待核验]] 记录了待核验事项；本轮补充 11 条外部来源（综述、预印本、期刊论文与科普文），按以下方法反查：

- 只有**两个及以上独立来源复现**的名称，才视为可确认；
- **单点出现**的名称记为「待核验」；
- 名称出现在非本任务来源（聚类、对齐、科普）中时，须区分「专名可确认」与「流派归属可确认」两件事。

一句话结论：五种流派的完整名单与关键论文在公开来源中**只被部分复现**；唯一直接列出「五种方法」的来源 [3] 只提供了 Method B 与 Method E 两条，其中关键论文名 "LLM4Onto 2025" 未获任何旁证；综述 [2] 则提供了可交叉引用的替代线索（Lippolis et al. 2025b、LKD-KGC）。

## 来源分层

### 综述型来源（提供上位分类法与引文线索）

- **[1] Semantic Web Journal 综述**（标题截断为 "From Manual to LLM-assisted: A Mapping Review on Ontology ..."）：按三分分类法组织本体构建方法，抓取片段中可见 manual 与 semi-automatic 两档，第三档被截断；从标题推断其第三档为 LLM-assisted（待核验）。该来源的价值在于提供一条「自动化程度」轴。
- **[2] arXiv 综述 "LLM-empowered knowledge graph construction: A survey"**（arXiv ID 2510.20345，按 ID 惯例为 2025 年 10 月提交）：第 3 章 "LLM-Enhanced Ontology Construction"，第 3.1 节 "Top-down Ontology Construction: LLMs as Ontology Assistants"，下分两个子类：
  - **3.1.1 Competency Question (CQ)-Based Ontology Construction**：引 **Lippolis et al. (2025b)**，提出两种互补的提示策略——"memoryless"（面向模块化构建）与受 **Ontogenia** 启发的反思式迭代法（reflective iterative method）。
  - **3.1.2 Natural Language-Based Ontology Construction**：引 **LKD-KGC（Sun et al., 2025）**，通过聚类文档摘要中抽取的实体类型，为开放域知识图谱快速归纳 schema。
  - 参考文献列表中另出现 **"Ontology Generation using Large Language Models"** 一题，其与 Lippolis et al. (2025b) 的对应关系未在片段中说明。
  - 片段只展示了 3.1（top-down）一支，是否存在 bottom-up 分支未在来源中体现（待核验）。

### 流派原文来源（唯一直接列出「五种方法」）

- **[3] Substack《Building Ontology with LLMs: Five Methods Compared》**（zerofuturetech.substack.com；与既有的「零点未来」系列来源 [[8-零点未来ai企业--26-第-2-集12分钟学习llm驱动ontology构建--1qph07e]] 是否同源待核验）。可确认的条目只有两条：
  - **Method B: Clustering-Driven**，标注关键论文为 **LLM4Onto 2025**；
  - **Method E: End-to-End Prompting**，其结论为「小模型 + 好提示词 ≈ 大模型」。
  - Method A、C、D 的名称与关键论文在抓取片段中缺失。

### 技术支撑型来源（聚类与对齐技术底座）

- **[4]**（PMC）以 BERT 作为文本聚类表示的研究，使用四种聚类算法：k-means、eigenspace-based fuzzy c-means、deep embedded clustering（第四种被截断）。
- **[5]**（arXiv）TopiCLEAR：以「嵌入聚类 + 自适应降维」（CLustering Embeddings with Adaptive dimensional Reduction）做主题抽取。
- **[7]**（Frontiers）以在线聚类 + 大语言模型对既有本体做**零样本扩展**（从流式数据中增补本体），指向 ontology extension 任务。
- **[6]**（Taylor & Francis）基于 BERT 与本体做「语义数据 interestingness」挖掘的研究。
- 以上文献构成 Clustering-Driven 路线（Method B）的技术底座，但**均未出现 "LLM4Onto" 这一名称**。

### 相关但归属需注意的专名

- **[8] BERTMap**：基于 BERT 微调 + 图结构的**本体对齐（ontology alignment）**系统。专名可确认，但任务是概念/schema **对齐**而非**构建**，引用时须与「本体生成」区分，否则会污染流派清单。
- **[9]**（arXiv）核领域知识图谱的自动化**多步构建**，可作为「多步流水线」类案例的候选，是否对应某一流派未知。
- **[10]**（Medium）科普文：把本体定义为图的蓝图/schema——与 [[本体schema与实例事实]] 的区分口径一致，可佐证本体与知识图谱的职责边界（见 [[本体与知识图谱职责边界待核验]]），但不能作为方法论证据。
- **[11]**（ResearchGate）面向工业标准的知识图谱本体框架。

## 分类口径冲突

1. **「五种」与「两分」不同构**：[2] 的 3.1 节按「提示/输入形态」分为 CQ-based 与 NL-based，并统一置于 "LLMs as Ontology Assistants" 的上位视角；[3] 则按技术路线列出五种方法。两套划分不在同一层级，不能互相替换或叠加计数。
2. **同一技术的归属冲突**：[2] 把「聚类实体类型」放进 NL-based（3.1.2）子类，[3] 却把 Clustering 独立为 Method B。说明「聚类」在两套分类中分别被视为「自然语言输入的一种处理方式」与「独立技术路线」。
3. **自动化程度轴 vs 技术路线轴**：[1] 的 manual / semi-automatic（/ LLM-assisted）是自动化程度轴，与五种流派的技术路线轴正交；引用时须说明维度差异，避免把 [1] 当作五流派的上位分类。
4. **前 LLM 文献的定位风险**：[4][5][6][8] 多为 BERT 时代的聚类/对齐工作，严格意义上不属于「LLM 驱动」；若纳入五流派清单，应标注为「技术底座/前身」而非「流派代表论文」。这与 [[llm建本体的四道坎]]、[[本体构建选型双轴]] 中可能需要区分「能力来源」的口径相关。

## 缺口

- **完整五种清单缺失**：只有 [3] 直接列出五种方法，且片段仅含 Method B 与 E；A、C、D 的名称与关键论文未知。
- **LLM4Onto 属高风险专名**：在 arXiv、Semantic Web Journal、Frontiers、PMC 等不同来源中零复现，需优先核验其真实性或正确拼写，而非继续当作既成事实引用。
- **Ontogenia 与 Lippolis 2025a/2025b 的对应关系未定**：综述中 2025a/2025b 的区分未展开；"Ontology Generation using Large Language Models" 是否为 2025b 的题名待定。
- **LKD-KGC 的完整名称、作者与发表信息**未知。
- 抓取截断造成的空白：[4] 的第四种聚类算法、[1] 的第三档自动化级别、[2] 的后续小节。

## 对既有页面的影响

- [[llm驱动本体构建五种流派]]：可补入 Method B / Method E 的名称与结论（小模型 + 好提示词 ≈ 大模型），并把 LLM4Onto 明确标注为高风险专名。
- [[五种流派论文与案例待核验]]：本轮把核验进度推进到「2 个方法名 + 4 个候选专名（LLM4Onto、LKD-KGC、Lippolis et al. 2025b、Ontogenia）+ 1 条上位综述（arXiv 2510.20345）」，其余事项保留待核验。
- [[ontoprompt]]、[[wikidata]]：本轮未获新证据，维持原状。
- 若后续确认 LKD-KGC、LLM4Onto 等为真实文献，可考虑为其建立独立实体页并与 [[owl]]、[[codex]] 等建模工具页区分开（前者是方法论文，后者是建模载体）。
