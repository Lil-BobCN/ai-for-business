# Research: GB/T 46917.2 与 GB/T 38672-2020、ISO 10303-22 接口规范比较

# GB/T 46917.2 与 GB/T 38672-2020、ISO 10303-22 接口规范比较

## 概述

本页对三项与"数据接口"直接相关的标准化成果进行定位级与结构级比较：[[gb-t-46917-2-2026-数据接口要求|GB/T 46917.2-2026]]《标准语义知识库 第2部分：数据接口要求》、[[gb-t-38672-2020-大数据接口基本要求|GB/T 38672-2020]]《信息技术 大数据 接口基本要求》，以及 ISO 10303-22:1998（STEP 实现方法中的标准数据访问接口，SDAI）。三者分属不同领域与不同技术代际：[[gb-t-46917-2-2026-数据接口要求|GB/T 46917.2]] 面向标准语义知识库的服务化数据接口；[[gb-t-38672-2020-大数据接口基本要求|GB/T 38672-2020]] 给出大数据接口的通用基本要求；ISO 10303-22 则是面向产品数据交换（STEP）的抽象数据访问接口。三者之间已确认的制度联系是：GB/T 38672-2020 被 GB/T 46917.2 列为规范性引用文件[2]；而现有证据未显示 GB/T 46917.2 与 ISO 10303-22 之间存在采标、引用或对标关系。

## 比较对象与证据基础

### GB/T 46917.2-2026《标准语义知识库 第2部分：数据接口要求》

该标准是 [[gb-t-46917-标准语义知识库系列|GB/T 46917 标准语义知识库系列]]的第 2 部分，同系列第 1 部分为 [[gb-t-46917-1-2026-标准内容语义化表达通用要求|标准内容语义化表达通用要求]]，第 3 部分为 [[gb-t-46917-3-2026-语义集成技术要求|语义集成技术要求]]。中国标准化研究院公开的该标准资料显示，其数据接口总体框架围绕数据供给方、数据库建设方等角色展开，并将 GB/T 38672-2020 列入引用文件[2]。依据征求意见稿全文整理的既有页面，其接口体系包括 [[标准语义知识库数据接口总体框架|数据接口总体框架]]、[[基础接口与高级接口|基础接口与高级接口]]、[[接口管理要求|接口管理要求]] 与 [[接口返回状态码|接口返回状态码]] 等组成部分，并含有问答接口示例等附录内容。需注意本页对其接口结构的描述主要基于 2025-04 征求意见稿，正式发布版可能存在差异。

### GB/T 38672-2020《信息技术 大数据 接口基本要求》

来源[1]给出的题录信息为：标准号 GB/T 38672-2020，中国标准分类号 L67，国际标准分类号 35.240，2020-04-28 发布，实施日期在来源中截断（为 2020 年）。其定位是大数据领域的通用接口基本要求，属于基础性、跨领域适用的接口规范；在 GB/T 46917.2 中被规范性引用[2]，即知识库领域接口要求在通用大数据接口要求之上做领域化细化。

### ISO 10303-22:1998（SDAI）

ISO 10303（俗称 STEP）的"实现方法"分部之一，官方标题为 Implementation methods: Standard data access interface，通常简称 SDAI[4][5][6]。其相邻分部构成一套"数据交换—访问接口—语言绑定"结构：Part 21 规定交换结构的明文编码（clear text encoding of the exchange structure），Part 22 规定标准数据访问接口，Part 23 提供该接口的 C++ 语言绑定（ISO 10303-23:2000）[3][6]，Part 24 提供 C 语言绑定，Part 26 提供接口定义语言（IDL）绑定[4]。ISO 10303-1:2021 的页面亦将该分部列为实现方法之一[6]。可见 SDAI 采用"语言无关的抽象接口 + 多语言绑定"的组织方式，与具体编程语言的接入相配套。

## 接口技术路径差异

**抽象层次与消费方式不同。** GB/T 46917.2 的接口划分（[[基础接口与高级接口|基础接口与高级接口]]）、[[接口管理要求|接口管理要求]] 与 [[接口返回状态码|接口返回状态码]] 表明它更接近面向服务调用的 API 规范，其附录中的问答接口示例（JSON 形式）也提示默认消费方式是系统间的数据服务调用；同时，[[数据接口建设与应用原则|数据接口建设与应用原则]] 一类内容说明其设计取向兼顾供给方与使用方的工程落地。ISO 10303-22 则是在程序内访问 STEP 数据的抽象接口，通过 Part 23（C++）、Part 24（C）、Part 26（IDL）等语言绑定映射到具体实现[3][4]，其默认消费方式是编程语言层面的 API 调用而非网络服务调用。GB/T 38672-2020 处于两者之间的大数据通用层面，具体条款形态因文本未获取而无法判断[1]。

**体系结构与引用关系不同。** GB/T 46917.2 与同系列第 1 部分（语义化表达）构成链条：先定义标准内容的语义化表达单元，再由数据接口规定知识库对外访问方式，后续由第 3 部分处理语义集成。ISO 10303-22 则嵌入 ISO 10303 的既有分部结构：Part 21 解决交换文件编码，Part 22 解决数据访问接口，后续 Part 23/24/26 解决语言绑定[3][4][6]，各分部相互配合而非单一文件独立成体系。GB/T 46917.2 与 GB/T 38672-2020 的关系则是明确的上位引用：按标准引用的通常含义，GB/T 46917.2 在通用大数据接口要求的基础上叠加标准语义知识库的领域约束[2]。

**时代与范式不同。** ISO 10303-22（1998）反映产品数据交换时代的"抽象接口 + 语言绑定"范式；GB/T 38672-2020（2020）反映大数据时期对通用接口基本要求的沉淀；GB/T 46917.2（2026）面向语义知识库场景，与语义化表达、知识组织等新需求结合。整体上呈现从"产品数据访问"到"大数据接口"再到"知识库服务接口"的代际递进。

## 可比性评估

- 三者在"为异构系统访问领域数据提供标准化接口"这一功能定位层面具有框架级可比性，均承担互操作职责。
- 但就条款级内容而言，三者的领域模型、接口抽象层次与消费方式差异较大；且 GB/T 38672-2020 与 ISO 10303-22 的条款级文本不在现有证据集内，本页只能给出定位与结构层面的比较。
- GB/T 46917.2 与 ISO 10303-22 的相似性主要是功能定位层面的（领域数据访问接口），并不构成承继关系；"国际一致性程度"问题在标准族层面仍待核验（参见 [[标准数字化标准族国际标准一致性程度待核验]]）。

## 矛盾与待核验事项

- **SDAI 名称表述差异**：来源[3]页面出现 "Standard data access interface specification" 表述，来源[4][5][6]为 "Standard data access interface"（SDAI）。以 ISO 官方标题为准的措辞待核验。
- **ISO 10303-22 现行版本状态未核验**：现有证据仅见 1998 年版条目[4]，是否存在后续修订或复审状态未知。
- **GB/T 38672-2020 条款内容缺失**：其接口要求的具体条款未获取，无法核对 GB/T 46917.2 对其的引用方式（引用哪些章条）；其"实施日期"在来源[1]中被截断。
- **GB/T 46917.2 的描述基于征求意见稿**：正式发布版与 2025-04 征求意见稿的差异待核验（参见 [[gb-t-46917-2正式版与2025-04征求意见稿差异待核验]]）；征求意见稿自身尚有若干待核验点，如 [[接口返回状态码章节引用错位待核验]]、[[接口参数名status大小写不一致待核验]]、[[表9与正文表11编号错位待核验]]、[[附录a问答接口示例json格式不规范待核验]]。
- **"国际处于领先水平"主张缺乏对标论证**：编制说明中的该主张尚未给出与任何国际接口标准的逐项比对细节（参见 [[gb-t-46917-2国际领先主张待核验]]）。
