# 面向制品与面向角色的拆解比较

本页并列比较两种降低语义跨度的拆解方式：面向制品与面向角色。前者来自视频作者 catface996 在《Ontology：AI Coding 在本体中的建模和实战》中的主张；后者与既有 [[concepts/从业务员工中培养自己的-fde]] 的取向相关。两者是否真正对立、还是互补，本页保留双方来源，不做静默取舍。

## 对照表

| 维度 | 面向制品 | 面向角色 |
|---|---|---|
| 拆解依据 | 做出来的是什么（需求、设计、任务、代码） | 谁来做（业务方、产品、架构师、开发、测试、运维） |
| 稳定性来源 | 结构（格式、流程图、时序图） | 个人经验 |
| 可标准化程度 | 高（作者主张） | 低（作者主张） |
| 主要风险 | 制品形态未定型时过早固化格式可能推高成本 | 同一角色不同人稳定性不一致 |
| 来源 | catface996 口播，`unknown` | 与 [[concepts/从业务员工中培养自己的-fde]] 取向相关 |

## 来源观点（均归属 catface996，`unknown / 待外部核验`）

- 作者明确倾向面向制品，理由是制品可标准化、角色不稳定。
- 作者把面向制品与面向角色都视为"降低语义跨度的方案"。

## 已核验事实

- 无。两种方式的优劣均为作者主张，未做独立核验。

## 项目分析

本比较页与既有 [[concepts/从业务员工中培养自己的-fde]] 形成方法论对照。两者可能并非真正对立：面向角色强调从业务员工中培养 FDE，面向制品强调制品格式标准化，二者在"把业务知识沉淀下来"这一目标上可能互补。

## 反例或边界

- 在制品形态还没稳定下来的团队里，先定义角色职责与先定义制品格式，哪一种更容易推进，作者未给出判断依据。
