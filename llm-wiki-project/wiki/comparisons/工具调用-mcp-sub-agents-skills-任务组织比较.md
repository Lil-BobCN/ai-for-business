# 工具调用、MCP、sub agents 与 skills 的任务组织比较

## 比较范围

本页比较视频作者对四种 Agent 接入或任务组织形态的描述。它不是完整的技术标准，也不构成通用选型结论。来源明确说明这些形态可以组合。

| 形态 | 来源中的主要角色 | 视频作者建议的场景 | 来源明确提到的代价或限制 |
|---|---|---|---|
| function calling／tool calling | 让 Agent 选择外部函数并提交参数 | 高频查询、业务更新、数据校验和自主操作 | 没有提供参数、权限和错误契约 |
| MCP | 在一个接入中封装多个查询、更新和校验子函数 | 查询、更新、巡检（原词待确认）和校验组成的较完整链路 | 作者提到上下文消耗和服务延时，但没有测量 |
| sub agents | 把更复杂的任务、多渠道操作或 workflow 分配给其他 Agent | 复杂任务、多个工具和工作流组合 | 没有展示任务拆分、状态共享和失败恢复 |
| skills | 将可复用任务能力或操作流程封装起来 | 轻量任务、固定流程和分支 | 来源没有定义执行语义和生命周期 |

## 三类任务分流

作者还给出一条更直接的分流规则：

- 固定流程和分支，使用 workflow 或 skills；
- 需要 Agent 自主决定操作路径，使用 tool calling 或 MCP；
- 需要人工介入的复杂任务，使用 sub agents 或 workflow 加 Agent，并显式定义人工节点。

这条规则适合作为方案讨论的起点，不能替代问题集、权限分析、性能测试和失败场景评测。

## 需要补充的评审维度

视频只明确提到 MCP 的上下文和延时成本。实际选型还需要验证：

- 工具权限和副作用；
- 参数与返回契约；
- 执行可观测性和来源溯源；
- 版本兼容和变更责任；
- 失败恢复、人工介入和审计；
- 评测集、延时、成本和错误率。

以上维度属于当前分析，来源没有提供测试结果。

## 结论边界

四种形态并不严格互斥。sub agents 可以调用工具或执行 workflow，skills 也可能与工具接口组合。不能把某一种形态写成所有场景下的最佳实践，也不能仅凭订单演示一次跑通就判断方案适合生产环境。
