# 企业 AI 语义层与 Agent 研究 Wiki

## Goal

把本项目收集的企业 AI、Ontology、FDE、RAG、知识图谱和 Agent 资料，整理成一个可追溯、可持续更新、能支持讨论和联网研究的个人知识 Wiki。

Wiki 的长期目标不是替代原始资料，而是帮助我：

- 快速定位某个概念、方法、工具或案例的证据；
- 比较不同作者或来源的观点；
- 显示资料之间的关系、矛盾和知识空白；
- 在本地资料不足时提出联网研究问题；
- 把我确认过的判断、决策和开放问题持续保存下来。

## Key Questions

1. 企业 AI 语义层由哪些部分组成，每一部分的边界是什么？
2. Ontology、知识图谱、Context Graph、RAG、GraphRAG 和 Agent 如何分工？
3. 企业 Agent 落地需要哪些数据、流程、权限、工具和人机协同机制？
4. FDE 的交付方法如何从资料和案例中提炼出来？
5. 哪些结论只是视频作者或文章作者的主张，哪些已经有一手资料支持？
6. 现有知识库还缺什么证据，下一步应该查什么？

## Scope

**In scope:**

- 工作区 `raw/` 中的三组资料；
- 资料的来源、索引、提取方式、SHA-256 和证据状态；
- 企业 AI、Ontology、FDE、RAG、知识图谱、Agent 和语义层相关概念；
- 经过明确来源标记的外部研究结果；
- 观点比较、冲突记录、开放问题和已确认决策。

**Out of scope:**

- 把 ASR 转写或视频作者观点直接当成已证实事实；
- 直接修改或重写原始 `raw/` 文件；
- 把没有 URL、日期和出处的联网摘要写入长期结论；
- 把未核验的产品宣传、数字或案例当成项目事实；
- 在没有人工确认的情况下自动发布高影响决策。

## Research Rules

1. 先查本地 Wiki 和 `raw/sources`，再决定是否联网。
2. 本地资料不足、存在冲突或涉及时效性时，提出明确的外部研究问题。
3. 外部研究必须记录 URL、访问日期、来源类型、关键摘录和适用范围。
4. 回答必须区分：来源原话、独立核验事实、当前分析、未验证假设。
5. 原始资料中的 `verified`、`partial`、`unknown / 待外部核验` 状态必须保留。
6. 同一结论若来自多个来源，应在页面中列出所有来源，不覆盖早期证据。
7. 发现矛盾时创建或更新 `wiki/queries/` 中的开放问题，保留双方来源。
8. 只有我明确确认的判断，才进入 `wiki/synthesis/` 或 `wiki/decisions/` 的长期结论。

## Current Thesis

> 企业 AI 的核心问题不是单独选择某个模型或 Agent 框架，而是把业务概念、数据、规则、权限、工具和人机协同组织成可验证的业务上下文。这个判断仍在研究中，不能视为最终结论。
