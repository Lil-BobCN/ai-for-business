# Douyin Reference Transcript 文档原型

> 这是格式原型，不是实际抖音提取结果。
>
> 三个原型使用同一段模拟口播内容，比较的是 Markdown 的信息层级、阅读顺序和 Agent 检索方式。

## 原型入口

| 原型 | 结构 | 适合场景 | 主要取舍 |
|---|---|---|---|
| [A-人类阅读优先](./01-A-人类阅读优先.md) | 摘要 → 大纲 → 完整口播 → 思考书签 → 解读 | 连续阅读、快速理解 | 阅读顺，但解读要读到后面 |
| [B-证据与解读并列](./02-B-证据与解读并列.md) | 元数据 → 摘要/大纲 → 论点链 → 完整口播 → 书签 | 研究、引用、讨论 | 信息密度最高，阅读负担略大 |
| [C-系列索引优先](./03-C-系列索引优先.md) | 系列索引 → 分集文件 | 多集系列、长期积累 | 适合管理系列，不代表单集正文结构 |
| [A-最终版：正文内嵌思考书签](./04-A-最终原型-正文内嵌思考书签.md) | 摘要 → 大纲 → 无时间戳正文 → 内嵌书签 → 解读 | 连续阅读、边读边产生思考 | 书签贴着原文出现，不另起阅读流 |
| [Ontology 阅读版原型](./05-Ontology-AI-Coding-阅读版原型.md) | 真实口播素材 → 连贯文章 → 内嵌思考 → 跨段解读 | 检验长篇技术口播如何被重新组织 | 不展示时间戳，不使用“原话锚点”标签，不附校订记录 |

## 已确定的共同规则

- 完整口播是证据层，不能被摘要或解读替代。
- 补足中文标点并按语义分段，忠实原话，不改写内容。
- 最终阅读版正文不展示时间戳。
- 思考书签紧跟在对应正文段落之后，不另起阅读流。
- 每条书签包含：原话锚点、思考问题、可延展方向。
- 解读包含：论点链、隐含前提、可核验主张、反例/追问、可迁移素材。
- 集数只采用链接或文案中明确出现的集数；无法确认时写“集数待确认”。
- 标题、专名和事实无法可靠判断时，写“待确认”或“待外部核验”，不擅自补齐。
- 系列文件夹采用：`00-系列索引.md`、`01-第1集-标题.md`、`02-第2集-标题.md`。
